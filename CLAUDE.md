# Инструкции для агентов, работающих в этом репозитории

Гефест — оркестратор Claude Code-агентов. Агенты здесь не гости, а штатные
коммиттеры: они открывают PR и работают в изолированных контейнерах.
Правила ниже описывают их периметр.

## Агенты коммитят только через форк

**Агент никогда не пушит ветку в `IgorKramar/gefest`. Работа идёт через форк,
PR открывается из форка.**

Причина не в аккуратности, а в правах. На событии `pull_request` GitHub
исполняет workflow **из головы PR**, а не из `main`. Значит PR, открытый из
ветки этого же репозитория, приносит собственный файл `.github/workflows/ci.yml`
— вместе с собственным блоком `permissions:`. Минимальные права, прописанные в
`main`, обязательны только для тех PR, которые этот файл не трогают.

Из ветки в том же репозитории агент может заменить workflow на
`permissions: write-all` с шагом выгрузки — и это исполнится **до того**, как
диф кто-то прочитает. Ворота ADR-0012 здесь не спасают: required review гейтит
мерж, а не запуск. CODEOWNERS на `.github/**` — тоже, по той же причине.

PR из форка получает read-only токен и не видит секретов репозитория. Разница
именно в правах, а не в исполнении кода: `mise run build` в любом случае
выполняет код из PR — форк лишает этот код токена и секретов.

**Практическое следствие:** scoped-токены из пула (ADR-0010) выдаются с правом
пуша в форк, но не в основной репозиторий. Токен, позволяющий создать ветку в
`IgorKramar/gefest`, обесценивает это правило целиком.

Когда появится первый секрет репозитория (пуш в GHCR, ключи деплоя), он живёт
в GitHub Environment с обязательным ревьюером, а не в секретах уровня
репозитория: workflow, управляемый головой PR, не должен читать его без
присмотра.

## Прямой пуш в `main` запрещён всем

Код попадает в `main` только через PR с зелёным CI (ADR-0012). Ruleset заведён
с **пустым bypass list** — правила действуют и на владельца. Практическое
следствие принято сознательно: документация тоже идёт через PR.

## Канон раскладки — один файл

«Куда класть код» описано в `ARCHITECTURE.md`, раздел «Структура (C4,
container)»: каталоги, имена пакетов и границы крейтов. Инструкции ссылаются
туда и не дублируют — разошедшаяся копия хуже отсутствующей.

Имена пакетов несут префикс `hef-` при каталогах без него: пакет с именем
`core` затеняет стандартный `core` в зависимых крейтах.

## SQL меняет владелец — до готовности брокера

Пока брокер ресурсов (GF-2) не выдаёт контейнеру задачи dev-БД, SQL-запросы в
`crates/db` меняет только владелец. У агента нет живой базы, а значит нет
честного пути перегенерировать `.sqlx`.

Регламент временный, условие снятия названо. Подробности и runbook —
`crates/db/README.md`.

## Проверки обязаны уметь краснеть

Любой сторож (CI-gate, валидатор) заводится вместе с доказательством, что он
способен упасть. Сторож, ни разу не показавший красного, считается
непроверенным: сломанный сторож молча зеленеет, и это неотличимо от здорового
состояния.

Проверка сторожей автоматизирована: `mise run guard:selftest`. Новый сторож
добавляется туда тем же изменением. Откуда взялось правило и пять конкретных
способов сломать сторожа —
`docs/solutions/best-practices/storozh-obyazan-krasnet.md`.

Отдельное правило для gate-ов: проверка легитимна, только когда у каждого
класса участников есть честный путь до зелёного **внутри своего периметра**.
Сторож, ловящий невозможность вместо забывчивости, порождает обходы —
см. `docs/solutions/best-practices/storozh-protiv-nevozmozhnosti.md`.

## Где искать накопленное

`docs/solutions/` — разобранные проблемы и практики, по категориям, с
YAML-фронтматтером (`module`, `tags`, `problem_type`, `applies_when`).
Пригождается перед работой в задетой области: часть граблей там уже описана
вместе с причиной и лечением.

`CONCEPTS.md` — словарь проекта: доменные сущности, именованные процессы и
статусные понятия. Термины оттуда используются в коде и документах как есть,
без синонимов.

## Авторство

Единственный автор всего, что попадает в этот репозиторий, — **Igor Kramar**.
Ни в коммитах, ни в описаниях PR, ни в коде, ни в документации не появляется
упоминаний ИИ, ассистента или соавторства: никаких трейлеров `Co-Authored-By`,
строк о генерации, пометок «AI-generated».
