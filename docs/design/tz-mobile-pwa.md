# ТЗ: мобильный PWA Гефеста

Норматив для макетов (Claude Design). Пара к `tz-web-panel.md` — токены, характер, шрифты, статусная шкала и доменные компоненты **общие** (разделы 2–3 и 6 веб-ТЗ действуют здесь дословно); этот документ описывает мобильные отличия. Русский язык; один пользователь — владелец.

## 1. Контекст использования

Телефон — **полноправный пункт управления** (не «просмотрщик»): владелец вне ноутбука должен разблокировать агентов и держать контроль. Профиль использования: **чтение чаще, действия короткие** — ответить на вопрос, принять/отклонить решение, остановить агента, глянуть статусы; длинная правка текста — редкость, но возможна. Сессии короткие (30–90 секунд), часто по алерту из Telegram/ntfy → deep-link прямо в нужный экран. Установка: PWA через «Add to Home Screen» (iOS) / WebAPK (Android), standalone-режим, вход по passkey (Face ID/Touch ID, same-origin).

## 2. Каркас

- **Нижняя навигация, 4 таба**: **Агенты** (глиф-горн) · **Решения** (клеймо, моно-бейдж непрочитанного) · **Чат** (бейдж) · **Задачи** (наковальня). Высота 56 + safe-area; активный таб — огненный глиф + подпись.
- Настройки — с экрана Агентов (шестерёнка-мехи в шапке). Журнал и Ресурсы в PWA v1 **не дублируются** (веб-задачи); доступ к ним — не рисовать.
- Шапка экрана: заголовок (Tektur), справа контекстное действие.
- Все касаемые цели ≥ 44 px. Никакого фейкового статус-бара и фейковой клавиатуры в макетах — системные рисуются поверх настоящей страницы; safe-area сверху/снизу оставить пустой.
- **Pull-to-refresh — свой** (нативного в standalone нет): огненная искра-спиннер под шапкой; overscroll-behavior управляем.
- Тёмная/светлая — по системной теме телефона (переключатель — в настройках).

## 3. Экраны

Состояния каждого экрана — как в веб-ТЗ (загрузка-скелетоны, пусто с характером, ошибка, реконнект-баннер); плюс **офлайн**: полноэкранное состояние «Нет связи с кузней» (глиф остывшего горна + повторить + подсказка «проверь VPN» — tailnet может быть выключен на телефоне, это частая причина).

### 3.1 Агенты (главный, пульт)

- Вертикальный список компактных карточек агентов: глиф роли + имя + статус (слово+цвет) + текущая задача (ключ моно) + последняя веха одной строкой + бейдж «почему стоит» / жёлтая метка «ждёт ответа».
- running-карточки сверху, огненная левая кромка; спящие приглушены внизу.
- Тап — экран агента. Свайп карточки влево — быстрые действия: **Стоп** (красный), **Указание**.

### 3.2 Агент (детализация)

- Шапка: роль, статус, задача. Ниже — мини-лента вех (последние 10, живо), псевдотерминальная строка.
- Крупные действия (ряд кнопок ≥44): **Ответить** (если ждёт — первая, жёлтая), **Указание**, **Стоп** (danger, с подтверждающим шитом «Остановить? Сессия сохранится, очередь указаний будет отменена»).
- Трасса доставки последних указаний (компонент из веб-ТЗ, вертикальная компоновка чипов).
- «Показать диалог» (срез сырья) — полноэкранный моно-просмотр, тёмный всегда.

### 3.3 Решения

- Та же единая очередь, что в вебе: pending-потоки + вопросы. Карточка: тип (клеймо), автор, контекст, содержимое (свёрнуто, тап раскрывает), возраст.
- **Свайпы**: вправо — Принять (огненная подложка тянется за пальцем, хаптика), влево — Отклонить (серая); свайп до половины — кнопки, до конца — действие. Отклонение просит опциональный комментарий (шит).
- **Вопросы агентов** — особые карточки: тап открывает **полноэкранный композер ответа** (поле, клавиатура сразу, кнопка «Ответить» уходит указанием с гарантией; трасса появляется в карточке после отправки).
- Бейдж таба = число карточек; после порога эскалации карточка помечается жёлтым «давно ждёт».

### 3.4 Чат

- Лента как в вебе (сообщения владельца — огненная метка), композер снизу над навигацией; переключатель «сообщение/указание» — компактный сегмент-контрол в композере.
- Прочитанность — точки-счётчик; длинные тексты сворачиваются.

### 3.5 Задачи

- Упрощённая доска: сегмент-контрол статусов сверху (Бэклог · В работе · Ждёт · Готово) + вертикальный список карточек выбранного статуса (ключ моно, заголовок, роль, статусная точка сессии, бейдж «почему стоит»).
- Тап — шит задачи: описание, последние события, сессии, кнопки Указание/Стоп. Создание задачи — FAB не нужен: кнопка «+» в шапке (создание с телефона — редкое, но возможное).

### 3.6 Настройки (с экрана Агентов)

Тема (системная/тёмная/светлая), уведомления (статус web push: не установлено/выключено/активно — с шагами включения; напоминание, что первичный канал — Telegram/ntfy), passkey-устройства, выход.

## 4. Уведомления и установка

- **Первичный канал алертов — внешний** (Telegram/ntfy/почта, ADR-0010): доставка не зависит от состояния PWA. Алерт содержит только факт+ссылку → **deep-link** открывает PWA сразу на нужном экране (вопрос агента → композер ответа; «пополни пул» → Ресурсы в вебе — на телефоне показать карточку-заглушку «открой с ноутбука» с копируемой ссылкой).
- **Web push — дублирующий канал** установленной PWA (iOS 16.4+; разрешение запрашивается по явному действию в Настройках, не при первом входе). **Badging API**: бейдж иконки = счётчик Решений.
- **Экран-приглашение установки** (один раз, ненавязчиво): для iOS — короткая инструкция Share → «На экран „Домой“» с глифами; для Android — системный промпт по beforeinstallprompt.
- После сброса процесса iOS (уход в другое приложение) состояние восстанавливается по URL — каждый экран и каждая карточка адресуемы (deep-link-first навигация).

## 5. Мобильная специфика компонентов

- Плотность на телефоне одна (между comfortable и compact: base 14, шаг 4/8/12/16/24, контролы 44); переключателя плотности нет.
- Шиты (bottom sheets) — основной модальный паттерн (Base UI Dialog в шитовой компоновке): скругление сверху 12, ручка-грип, свайп-вниз закрывает.
- Хаптика: свайп-действия и подтверждение «Принять/Стоп» — лёгкий тап.
- Псевдотерминал и моно-данные не сжимать ниже 11.5 px.
- Ландшафт не проектируется (портрет-only в манифесте допустим).

## 6. Чего НЕ делать

Всё из раздела 9 веб-ТЗ, плюс: не рисовать фейковый статус-бар/клавиатуру/чёлку в макетах экранов; не прятать «Стоп» глубже одного шага от карточки агента; не заводить гамбургер-меню (4 таба + шапка исчерпывают навигацию); не полагаться на web push как единственный канал чего бы то ни было; не делать онбординг-карусель — первый экран сразу пульт.
