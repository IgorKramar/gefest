# Futurist: модель доставки (D-4)

**Target**: docs/architecture/research/2026-08-20-model-dostavki-decision.md
**Date**: 2026-08-20 · **Horizon**: 1–3 года (фокус 2)
**Confidence note**: структурные — высокая уверенность; трендовые — спекуляция с сигналами.

## Summary

Главная ось старения — решение стоит на *наблюдённом* поведении CLI (S3/S4), не на контракте: каждая смена поколения CLI перепроверяет фундамент delivered. Вторая ось — двери, стремящиеся стать умолчаниями (requires_ack) или расшириться за модель (D-9-чат). Ядро устроено так, что стареет заменяемыми слоями — документ станет legacy предсказуемым образом, редкое качество.

## Structural findings — high-confidence

### F-1: S3/S4 — снимок, не контракт; прослойка CLI покрывает форматы, не семантику очереди
**Severity**: high · **Horizon**: первый мажорный релиз CLI, 6–12 мес, повторяется

delivered держится на трёх недокументированных фактах (очередь mid-turn, отсутствие эха, FIFO). Смена *поведения* CLI (начал эхоить, изменил момент забора, дропает очередь при abort) молча меняет смысл delivered — таблицы показывают «доставлено», свидетельство не свидетельствует: боль №2 в новом обличье. **Mitigation**: S3/S4(/S5) — исполняемые контрактные тесты прослойки CLI (вход D-6), прогон при каждом обновлении; версия CLI пинуется и обновляется решением.

### F-2: requires_ack-дверь дрейфует к умолчанию — жизнь в отвергнутой C без решения
**Severity**: medium · **Horizon**: ~1 год

Каждый ложный delivered → рациональное «включим ack для класса»; сумма через год — ack почти везде = альтернатива C со всей ценой, против которой возражали конституционно. Дверь без счётчика — рампа. **Mitigation**: бюджет в ADR-0007 — «requires_ack больше N классов = пересмотр D-4, не очередное включение».

### F-3: D-9-чат сядет на инбокс — предсказуемые расширения не помещаются в модель указаний
**Severity**: medium · **Horizon**: цикл D-9, 6–12 мес

Чат попросит: broadcast (N доставок на «всем»), каналы, чтение не-адресатом, «прочитано»≠«доставлено»; острее всего — спящий адресат: delivered-по-потоку требует живого процесса, а будить контейнер ради нерочного сообщения — против C-С1; нужна легальная семантика «queued до естественного пробуждения», иначе панель зарастёт вечными «недоставленными». **Mitigation**: `command` ≠ `message` в перечислении вида с v1; для message — нетерминальное долгое queued без эскалации и пробуждения.

### F-4: «1 ручной слот владельца» — синглтон, ломающийся на втором операторе
**Severity**: low · **Horizon**: событие «второй оператор» (тогда — medium)

Схема данных ко второму оператору готова (автор/адресат), планировщик — нет: «чья прямая команда идёт при исчерпанном окне» станет политикой, зашитой константой; два слота жгут окно друг у друга. **Mitigation**: слот — per-operator настройка с инвариантом «сумма ручных слотов ≤ резерв квоты».

## Trend findings — speculative, with named signals

### F-5: Документированный interrupt через stdin появится в горизонте ~1 года — «только SIGTERM» устареет
**Severity**: medium · **Confidence**: medium

Сигналы: capability `interrupt_receipt_v1` уже в system/init (версионированный id в handshake — подготовленный протокол); feature request `{"type":"interrupt"}` — anthropics/claude-code #41665 (март 2026); TS-SDK экспонирует interrupt(). Риск не в отсутствии триггера пересмотра, а в прорастании SIGTERM-семантики в UI, схему вех и привычки — пересмотр из правки модуля станет правкой продукта. Тот же релиз — главный кандидат сменить семантику очереди (F-1): два дрейфа придут одним обновлением. **Mitigation**: «стоп» в вехах/UI — класс прерываний (сегодняшняя реализация — SIGTERM). **Would change my mind**: wontfix #41665 или год тишины.

### F-6: Лимит-политика заточена под одну ось — Anthropic меняет правила чаще раза в год
**Severity**: medium · **Confidence**: medium

Сигналы: за год — недельные капы (07.2025), off-peak эксперимент (03.2026), удвоение 5h-окна (05.2026); недельный reset фиксированный — вторая ось с другой геометрией; прецедент DeepSeek: тарифная геометрия провайдера формирует чужие планировщики (целый класс «работай ночью»-плагинов). При недельном капе «ручной слот дожигает остаток недели, после чего стоят все» — политика одной оси вредна на другой; rate-limits.json нестабилен — каждая смена правил меняет подсказку. **Mitigation**: политика двухосевая с v1 (5h + weekly; weekly исчерпан — стоит всё), оси — конфиг. **Would change my mind**: год стабильности правил Max.

## What's likely to age well

delivered-по-потоку как принцип (уязвим носитель, не идея); истина в таблицах/stdin — транспорт (замена транспорта не трогает схему); at-least-once честно — физика, не мода; сон-экономика ценнее с ростом исполнителей; §4 как жанр — карта устаревания для будущего инженера, который не был при S3/S4.

## What's worth deciding now to defer pain

F-1: контрактные тесты + пин CLI. F-2: бюджет двери. F-3: command≠message с v1, долгий queued для message. F-4: слот per-operator. F-5: «стоп» как класс. F-6: две оси лимитов в конфиге.
