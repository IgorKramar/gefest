# Roast: model-dostavki-decision (D-4)

**Target**: `docs/architecture/research/2026-08-20-model-dostavki-decision.md`
**Date**: 2026-08-20
**Roles run**: devil-advocate (B-N), pragmatist (H-N), junior-engineer (J-N), compliance-officer (C-N), futurist (F-N)

## Headline findings

- **Devil-advocate**: у «delivered-по-потоку» нет каузальной связи с указанием — активный ход шумит событиями сам, инжект не эхоится; delivered ≈ sent+heartbeat, а reconciliation по тому же признаку либо теряет, либо дублирует (B-1+B-2); гонка «ответ во время остановки контейнера» — тихий deadlock центрального сценария (B-6).
- **Pragmatist**: §5 — шесть подсистем одной строкой = 60–100 часов ≈ квартал темпа против «Ф0 — 2 недели»; отладка «почему не delivered» не спроектирована; тесты против живого CLI нежизнеспособны — нужен фальшивый исполнитель (H-1…H-4).
- **Junior-engineer**: `delivered` не определяет, какое событие считается и сколько ждать; «ADR-0005 §CC-9» и «DoD Ф0 из ADR-0001» — ссылки на несуществующие имена; «по типу сбоя» без типологии (J-1, J-2, J-4).
- **Compliance-officer**: текст указания — носитель клиентских данных без классификации, retention и «удалить с производными»; ручной слот — привилегия без названного механизма аутентификации (C-1, C-4).
- **Futurist**: S3/S4 — снимок поведения, не контракт: смена поколения CLI молча меняет смысл delivered; requires_ack-дверь без бюджета дрейфует в отвергнутую альтернативу C (F-1, F-2).

## Cross-cutting concerns

- **CC-1. Каузальность delivered** (B-1, B-2, J-1; спайк S5 агрегатора): num_turns — не маркер (S5: склейка очереди, FIFO подтверждён); честная модель: idle-запись → delivered по началу новой активности; mid-turn-запись → delivered по активности **после** `tool_result` инструмента, in-flight на момент записи; error-события не считаются; таймаут наблюдателя — настройка. Reconciliation: перекладывать всё sent без каузального delivered (выбор «дублируем, не теряем») + дедуп вручений раннером по uuid.
- **CC-2. Stop и очередь** (B-5): stop переводит queued/sent-неподтверждённые указания сессии в `cancelled_by_stop`; запись в stdin и SIGTERM сериализуются writer-ом (EPIPE — штатная ветка).
- **CC-3. Сон и гонка** (B-6, H-3): v1 — **без** остановки контейнера (RAM 1–2 ждущих — копейки; версия pragmatist принята), спящий = процесс жив, reaper знает состояние `sleeping`; стоп-по-таймауту — код за флагом, включается при >2 одновременно спящих, с **двухфазным барьером** (`stopping` в таблице блокирует вручения → ответ падает в queued → после остановки `sleeping_cold` → ответ будит resume-ом); край «resume не взлетел» (перезагрузка хоста, битый транскрипт) — путь ретрай-машины с повторной доставкой вопроса+ответа в свежий контекст.
- **CC-4. Ретраи и side-effects** (B-8, J-4): типология сбоев — артефакт GF-2 (границы: «живой контекст» = транскрипт восстановим `--resume`); перед авто-ретраем — сверка observations и вех («работа, похоже, сделана» → не ретраить, синтетическое «предположительно завершено» + вопрос владельцу); side-effect-указания не ретраятся слепо.
- **CC-5. Лимиты и слот** (B-7, F-6, F-4): политика двухосевая (5h + weekly; weekly исчерпан → стоит всё + уведомление); ручная команда при жёстком отказе → `limit_blocked` + уведомление (не ретраи); метрика голодания фона (возраст старейшей фоновой задачи) — детектор границы пересмотра; слот — per-operator настройка с инвариантом суммы.
- **CC-6. Приватность указаний** (C-1, C-2, C-3, C-5, C-6): таблицы команд/инбокса наследуют scope_class; retention тела указания = 90 дней (факт доставки — вечно); «удалить с производными» включает тексты команд; opt-out «Improve Claude» — предусловие эксплуатации (проверить руками); алерты — только факт+ссылка, ноль свободного текста; белый список полей api_retry-вех; вопрос агента — событие session_events (под scope_class), ответ — указание.
- **CC-7. Аутентификация ручного слота** (C-4): механизм (сессионная auth панели поверх VPN; owner-эндпоинты недостижимы из сети исполнителей) — явная отсылка в D-7 строкой ADR-0007, не молчание.
- **CC-8. Контракт против снимка** (F-1, F-5): S3/S4/S5 — исполняемые контрактные тесты прослойки CLI (вход D-6), прогон при каждом обновлении CLI; версия CLI пинуется; «стоп» в вехах/UI — класс прерываний (реализация сегодня — SIGTERM), приход документированного interrupt (#41665, interrupt_receipt_v1) — добавление реализации.
- **CC-9. Фазировка GF-2** (H-1…H-6): 70%-ядро (writer + каузальный delivered + SIGTERM + reconciliation + фальшивый исполнитель + поле «почему стоит» в панели + лог решений планировщика); планировщик v1 — глобальный потолок + ручной слот + FIFO (priority-колонка есть, сортировка позже); пер-ролевые квоты и классификация ретраев — итерация 2; requires_ack — решение-дверь в ADR (бюджет: >2 классов = пересмотр D-4), кода в v1 нет; один авто-ретрай в v1 (3 — после типологии). Календарная честность: ядро 4–6 недель темпа.
- **CC-10. Текст** (J-3, J-5…J-10): CC-9→«ADR-0005, раздел Правила»; DoD Ф0 приравнять к decision консолидации ред. 2; «экспоненциальная проба» и «таймаут потока» определить с числами-настройками; «C-дверь» — скобка; синтетическое закрытие — предложение; итоговые перечисления — делегировано GF-2 с границами «не уже ADR-0005»; легенда — словарь docs/03 §3 + развести «ход»/«шаг»; command ≠ message в перечислении с v1, message может лежать queued долго без пробуждения (F-3).

## What survived

Ядро выбора — у всех пяти линз: push + подтверждение без участия модели, истина в таблицах/stdin как транспорт, at-least-once честно, отказ от pull (B), SIGTERM как stop, сон-экономика. Futurist: «документ станет legacy предсказуемым образом — редкое качество». Спайки собственным исполнением (S3/S4/S5) отмечены как сильная практика всеми ролями.

## Recommended path

**Apply and proceed** — выбор A не оспорен; 36 находок закрываются ред. 2 (каузальный delivered CC-1 — главная содержательная правка; фазировка CC-9; приватность CC-6; текст CC-10). Re-roast не требуется: правки уточняют механизм внутри выбранной модели. Владельцу на подтверждение: (1) v1 без остановки спящих контейнеров (упрощение против C-Д4а, экономика не страдает); (2) v1-планировщик упрощён (пер-ролевые квоты — итерацией 2); (3) requires_ack в v1 — только решение, без кода.
