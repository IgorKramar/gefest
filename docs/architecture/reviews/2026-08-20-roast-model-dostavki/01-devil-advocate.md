# Devil's advocate: модель доставки (D-4)

**Target**: docs/architecture/research/2026-08-20-model-dostavki-decision.md
**Date**: 2026-08-20

## Summary

Центральный инвариант «sent ≠ delivered» нарушается конструкцией `delivered`: «следующее stream-json-событие» неотличимо от фонового шума активного хода (B-1), а reconciliation по тому же наблюдению теряет или дублирует (B-2). Вторая по силе — гонка «ответ во время остановки контейнера» (B-6): вечно ждущий агент при формально доставленном ответе — боль №2 внутри системы, построенной её лечить.

## Attacks

### B-1: Ложный delivered — поток продолжился по своей причине
**Type**: логическая несостыковка · **Severity**: high

Во время активного хода процесс генерирует события непрерывно (дельты, tool_use, tool_result шедшего вызова). Раннер пишет mid-turn, через 300 мс приходит tool_result старого вызова — наблюдатель ставит delivered, хотя указание лежит в очереди CLI и до модели не дошло. Research фиксирует: инжект **не эхоится** — у наблюдателя нет ни одного сигнала, каузально связанного с указанием. «Подтверждение» наблюдает пульс процесса, не доставку: sent + heartbeat, переименованные в delivered. На команде «стоп по-старому, делай иначе» панель показывает «доставлено», агент делает не то — дословно боль №2. **Where**: §1 п.2; §3 признаёт косвенность, но не каузальный разрыв.

### B-2: Reconciliation-окно определено через ненаблюдаемое событие — оба исхода плохи
**Type**: failure mode · **Severity**: high

«Умер между sent и границей шага → переложить в queued» — но границу раннер не видит (B-1). Вариант 1 (перекладывать не-delivered): ложный delivered за миллисекунды до смерти → указание теряется терминально. Вариант 2 (перекладывать всё sent умершего): каждый crash → гарантированный дубль каждого недавнего указания (→ B-3). Какой выбран — не сказано; выбор «теряем или дублируем» — ядро модели, не деталь GF-2. **Where**: §1 п.2.

### B-3: Идемпотентность повтора — на дисциплине модели, которой проект не доверяет конституционно
**Type**: логическая несостыковка · **Severity**: medium

§2 отвергает B за зависимость от дисциплины модели — и §1 п.2 кладёт ту же дисциплину в failure path («исполнитель инструктирован игнорировать дубль по uuid»), причём в худший момент: после сбоя, resume и синтетического закрытия. Для side-effect-указаний («перезапусти миграцию», «запушь») проигнорированный дубль = двойное исполнение. A совершает грех B — просто реже и в самом опасном месте. **Where**: §2 против §1 п.2/§3.

### B-4: Очередь stdin >1 — порядок и склейка не проверены, решение на них стоит
**Type**: hidden assumption · **Severity**: medium

S4 — одно сообщение; FIFO — «предположительно», «FIFO?» прямо в плане тестов. «Делай X» + через 5 с «отставить, делай Y»: склейка → модель сама решает приоритет; по одному на границу → «отставить» приезжает шагом позже начала X. `priority` не действует в очереди уже живого процесса. Pipe buffer ~64 КБ: длинное указание при неготовом читателе блокирует синхронный writer → встаёт планировщик. **Where**: §1 п.1, §5. *(Примечание агрегатора: S5 после roast подтвердил FIFO и склейку в одно продолжение.)*

### B-5: SIGTERM конкурирует с записью — stop не инвалидирует очередь
**Type**: concurrency bug · **Severity**: medium (high для side-effect)

Гонка writer × stop: (а) обрубленный JSON в умирающий процесс; (б) EPIPE без оговорённой обработки; (в) указание sent в процесс, убитый нашим же стопом → reconciliation вернёт его в queued → после resume модель получит устаревшее «делай X», отданное ДО стопа — возможно, стоп и был из-за X. Семантика «stop инвалидирует очередь сессии» отсутствует; без неё стоп = «прерви сейчас, доиграй потом». **Where**: пересечение §1 п.1 × п.2; тестов на гонку нет.

### B-6: waiting_answer — ответ во время остановки контейнера
**Type**: concurrency bug · **Severity**: high

Раннер начал остановку, ответ пришёл, сессия в таблицах «живая»: ответ → stdin умирающего → sent; предсмертная активность (SessionEnd-хуки) → ложный delivered по B-1; ответ не в транскрипте; resume поднимает сессию, ждущую ответа, инбокс считает его вручённым терминально. Взаимная блокировка без автомата, имеющего причину вмешаться; обнаруживает владелец вручную. Ломает Д3 и DoD «спящий разбужен» (демо пройдёт по счастливому пути). **Where**: §1 п.4 — переходное «останавливается» не существует как состояние.

### B-7: Ручной слот при исчерпанном лимите — судьба команды не определена, фон голодает
**Type**: edge case · **Severity**: medium

При жёстком исчерпании API откажет и ручной команде: в очередь не встаёт (слот «вне паузы»), под ретраи не попадает («не по лимитам») — состояние нигде. Колебательный режим: окно сбросилось → 5 фоновых + ручная работа съедают его за час → фон снова стоит; голодание фона неограниченно, детектора границы пересмотра нет. **Where**: §1 п.5, §4.

### B-8: Ретраи через resume — детерминированный сбой контекста и retry-after-success
**Type**: failure mode · **Severity**: medium

«По типу сбоя» без типологии. Отказ 1: сбой вызван содержимым контекста → resume воспроизводит его 3 раза → ретраи потрачены на воспроизведение бага. Отказ 2 хуже: result при обрыве может не быть — «прервано» синтетическое неотличимо от «упало после сделанной работы» (коммит запушен, миграция применена) → ретрай повторяет сделанное; при чистом рестарте модель даже не видит первого захода. Классический генератор двойных side-effects; §5 тестирует счётчик, не семантику. **Where**: §1 п.6, §7.

## Strongest single attack

**B-1 + B-2 в связке**: delivered без каузальной связи + reconciliation по тому же признаку = проект с символом веры «sent ≠ delivered» выбрал модель, где delivered ≈ sent при живом процессе. Минимальное требование до GF-2: доказать существование наблюдаемого события, каузально привязанного к обработке нашего сообщения (спайк S5), и запретить delivered по событиям, стартовавшим до записи.

## Gaps in your own analysis

Внутренности stream-json оценены по research, не по сырым протоколам — если есть каузальный маркер, сила B-1/B-2 падает до «в decision не сказано, что наблюдатель к нему привязан» *(агрегатор: S5 нашёл маркер — активность после in-flight tool_result)*. Механика перекладки ADR-0005 «предварительная» — B-2 атакует невыбранность стороны. Стоимость наблюдателя, RAM спящих, смена CLI — pragmatist/futurist.
