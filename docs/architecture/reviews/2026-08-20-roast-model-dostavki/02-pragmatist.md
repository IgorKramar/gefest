# Pragmatist: модель доставки (D-4)

**Target**: docs/architecture/research/2026-08-20-model-dostavki-decision.md
**Date**: 2026-08-20

## Summary

Решение операционно самое дешёвое из рассмотренных, но §5 перечисляет шесть подсистем одной строкой — честная цена 60–100 часов = 2–3 месяца темпа против «Ф0 — 2 недели». Через полгода боль — не механика, а отладка планировщика и неразбуженные спящие.

## Operational findings

### H-1: Честный объём GF-2 — 2–3 месяца, не «Ф0 — 2 недели»
**Category**: cost · **Severity**: high

Покомпонентно: writer+наблюдатель 12–20 ч, планировщик 15–25, SIGTERM-обвязка 5–8, sleep/resume 8–15, ретраи 8–12, reconciliation 4–8, тестовая обвязка 10–15 = 60–100 ч поверх v1-ядра схемы и брокера контейнеров. При ~10 ч/нед — 6–10 недель на одну доставку; GF-2 целиком — квартал двойного учёта. Расхождение в 3–5 раз признать до старта.

### H-2: Отладка «почему не delivered» в 3 ночи не спроектирована
**Category**: on-call burden · **Severity**: high

Пять причин «висит» выглядят одинаково: квота роли, лимит-пауза, проба без resets_at, сон без resume, sent в зависший mid-turn. Нужно с первого дня (часы, не дни): поле **«почему стоит»** (quota/limit/probe/sleeping) у указания в панели; лог-строка на каждый переход с uuid/session_id; один алерт «sent без delivered > N сек». Иначе runbook по умолчанию — grep по 0700-файлам ночью.

### H-3: Sleep/resume — айсберг; «resume не взлетел» не назначен никому
**Category**: hidden overhead · **Severity**: high

Остановленный контейнер держит том, worktree и клон dev-БД — reaper-у нужно состояние «спит, не сирота», иначе sweep убьёт спящую задачу. Край: хост перезагрузился/образ обновился/транскрипт побит — resume несуществующего пути; «сбой пробуждения» — тот же ретрай-путь или отдельный? Молчание. Fallback «чистый рестарт» требует повторной доставки вопроса+ответа в свежий контекст — сценария нет ни в §5, ни в §7.

### H-4: Тесты §5 нельзя гонять против живого CLI — нужен фальшивый исполнитель
**Category**: tooling · **Severity**: high

Против настоящего CLI тесты (а) жгут общее 5h-окно — ресурс всех и владельца; (б) минуты стенного времени; (в) недетерминированы («SIGTERM ровно во время tool-вызова» не воспроизводится). Нужен фальшивый исполнитель (бинарь: эмитит stream-json, читает stdin, честно умирает по SIGTERM, управляемые задержки) — 10–15 неучтённых часов; без него тесты мигают и их перестают запускать = отсутствие тестов у машины гарантий. «(FIFO?)» прямо в плане — план ещё гипотеза.

### H-5: Планировщик — самый толстый компонент; каждое решение должно быть объяснимо
**Category**: operational debt · **Severity**: medium

Квоты 2 уровней + слот + приоритеты + лимит-пауза + проба + уведомления — машина богаче самой доставки. Steady-state вопрос «почему X не стартует» должен отвечать планировщик сам: «роль kst: 2/2 заняты Y, Z». Лог решений — +2–4 ч сейчас против 10–20 минут реконструкции по несколько раз в неделю навсегда.

### H-6: requires_ack-дверь — строить сейчас или отложить целиком; среднего нет
**Category**: operational debt · **Severity**: low

Ближе к medium при раннем включении двери. Даже выключенная требует колонку, MCP-инструмент, таймеры, ветку delivered — мёртвый путь, который упадёт при первом включении, потому что не гонялся. ADR-0005 уже даёт право forward-миграции — оставить дверь *решением* в ADR-0007, не кодом. Кандидат №1 на вычёркивание из GF-2.

## What's understated in the proposal

«resume — секунды» (после перезагрузки хоста — несуществующий путь); «минимум кода» (верно для транспорта — одного компонента из семи); «первый лимит-инцидент документирует себя» (= первый инцидент и есть тест парсера; приемлемо только с написанным fallback-путём); «перекладывает в queued (закрываемо)» (прячет порядок >1 указания после reconciliation — FIFO не обещан).

## What's missing entirely

Спецификация трассы доставки в панели; алерт «sent без delivered дольше N»; поведение спящих при перезагрузке хоста; порядок доставки нескольких queued после reconciliation; runbook как жанр (допустимо заменить полем «почему стоит» — но назвать это явно).

## What's actually realistic

70%-версия v1 за 4–6 недель темпа: writer + delivered-по-потоку + SIGTERM-stop с синтетическим закрытием + reconciliation + **фальшивый исполнитель** + **«почему стоит» в панели** — ядро, лечащее боль №2, не резать. Планировщик упростить: глобальный потолок 5 + ручной слот («команды владельца минуют паузу» — дёшево), колонка priority есть, сортировка FIFO; пер-ролевые квоты и приоритетная сортировка — итерация 2 по данным панели. `waiting_answer` — **без остановки контейнера в v1** (простаивающий процесс токены не жжёт; RAM 1–2 ждущих — копейки; стоп-по-таймауту — когда спящих станет >2). Ретраи: один авто чистым рестартом → paused + инцидент; классификация — итерация 2. requires_ack — дверь в ADR, кода нет. Всё отложенное покрыто правом forward-миграции — теряется только объём первого захода.
