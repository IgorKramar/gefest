## Headline findings

1. **C-1 + F-7 + проверка первоисточника (high)** — пилот A в задуманном виде не «серая зона», а нарушение Consumer Terms Anthropic: креды аккаунта нельзя делать доступными третьим лицам (§2), автоматизированный доступ — только через API-ключ или где явно разрешено (§3). Headless `claude -p` — официальная функция Claude Code → путь B аргументируем; монтирование подписочных кредов в песочницу стороннего продукта (yao) — под запретом по букве. Без подписки путь A требует API-токенов (нарушает C-Н1) либо не-Claude исполнителей (нарушает ответ №1) → **SS-1 предрешён условиями использования, не техникой**.
2. **B-5 + H-5 (high)** — пилот создаёт три источника истины, а детекторы расхождений не видят yao: решающая неделя слепа ровно к классу отказов AD-7.
3. **B-6 + H-4 + H-2 + F-2 (high)** — Ф0 недооценена: супервизор процессов с переподхватом после рестарта, идемпотентностью доставки и явной проверкой кредов (двойная молчаливая мода отказа: код 0 + DEVNULL) — 8–12 дней, не «немедленно».
4. **H-3 + H-7 + C-2 (high)** — эксплуатация без тросов: вывод vault убивает единственный git-бэкап знаний (restore не в DoD), нет ни одного канала уведомлений, git-токены в решении не упомянуты вовсе.
5. **B-1 + B-3 + J-3/J-4 (high)** — «бинарность» ворот иллюзорна: «впритык» без процедуры констатации, SS-1/SS-3 непроверяемы по написанному, критерий обходится двумя маленькими задачами и не проверяет С4.

## Cross-cutting concerns

- **Кластер 1 — ToS (C-1, F-7 + первоисточник):** пути A и B различаются классом договорного риска; decision этого различия не делает. Меняет суть решения.
- **Кластер 2 — пилот слеп и нечестен (B-1, B-3, B-5, H-1, H-5, J-3, J-4, J-5):** субъективные вердикты, невидимые расхождения, нереалистичный бюджет времени (7–10 ч на пять SS), обходимый критерий.
- **Кластер 3 — Ф0 и отказы раннера (B-6, H-2, H-4, F-2):** рестарт гасит cgroup, переподхват не описан, идемпотентность не оговорена, интерфейс CLI — не контракт, нужна своя прослойка.
- **Кластер 4 — эксплуатация (H-3, H-7, C-2, B-7):** бэкап+restore до Ф3, heartbeat, матрица секретов включая git-токены, ротация кредов по N песочницам.
- **Кластер 5 — периметр и чужой код (C-3, C-4, C-5):** «VPN-only» как принцип ADR; пилот только на некоммерческом репо + egress-аудит; вывод из Supabase с дедлайном.
- **Кластер 6 — самодостаточность документа (J-1…J-9, M-3 из meta-review):** легенда кодов, один алфавит, процедуры SS, представление имён.
- **Кластер 7 — дрейф (F-1, F-3, F-5, F-6, F-9, B-8):** календарная ревизия триггеров §4; обратный экспорт из yao с первого дня; поле автор/адресат в схеме B; дедлайны у «решается при Document»; граница «тонкого» B; стоп-сигналы для исхода B.

## What survived

Конструкция «ворота + default-to-B + тайм-бокс»; асимметрия обратимости как рамка; Ф0 как инвариант обоих миров; «done = состояние внешнего мира» + детекторы (самая переносимая ценность); резолюция П-1 (compose); ловушка S1b, поймана до продакшена.

## Recommended path

**Step back (to Decide)** — кластер 1 меняет посылку решения, выбор за владельцем до применения правок:

- **(а) Исход B напрямую** — пилот A отменяется по договорному основанию; yao/DSH — доноры идей; новый триггер пересмотра: легализация подписочного использования / одобрение yao / бюджет на API-токены. Применить кластеры 3–7. ← рекомендация агрегатора.
- **(б) Пилот с осознанным принятием ToS-риска** — письменная фиксация принятия риска бана аккаунта Max; кластеры 2–7 обязательны (некоммерческий репо, egress-аудит, регистрация задач в базе, процедуры SS). Не рекомендуется: цена реализации — остановка команды.
- **(в) Запрос в Anthropic до пилота** — путь легализации A; на время ожидания действовать по (а); Ф0 не ждёт ничего.

После выбора владельца: применить правки к decision (+ design: дописать композицию как альтернативу E — находка M-6 meta-review), затем re-roast не требуется (кластеры 2–7 — правки плана, не пересмотр выбора), переход к Document.
