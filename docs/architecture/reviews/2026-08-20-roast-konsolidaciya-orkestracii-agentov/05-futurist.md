# Futurist: konsolidaciya-orkestracii-agentov-decision

**Target**: docs/architecture/research/2026-08-20-konsolidaciya-orkestracii-agentov-decision.md (+ discovery, research, design)
**Date**: 2026-08-20
**Horizon**: 1–3 года, фокус на 2 годах, оба исхода пилота (A: yao, B: свой оркестратор)
**Confidence note**: структурные находки — высокая уверенность; трендовые — умозрительны, допущения и сигналы названы.

## Summary

Само решение сконструировано добротно: ступенчатость, бинарные стоп-сигналы, исход по умолчанию B — это переживёт два года лучше, чем любой из вариантов, которые оно выбирает. Самый значимый дрейф — не в выборе A или B, а в двух местах без хозяина: **интерфейс к Claude Code CLI** (сменится при любом исходе, а обвязка обоих миров стоит на недокументированных деталях) и **границы пересмотра §4, у которых нет наблюдателя** — пассивные триггеры без даты и ответственного за два года не срабатывают, они тихо истлевают.

## Structural findings — high-confidence

### F-1: Триггеры пересмотра §4 пассивны — через год их никто не проверит
**Severity**: high · **Type**: adjacent decisions / team · **Horizon**: 6–12 месяцев

Четыре из пяти триггеров — события во внешнем мире; чтобы «DSH дозревает» сработал, кто-то должен читать релизы DSH в марте 2027-го — а к тому моменту контур работает, боли нет, никто не читает. Пятый («3 месяца без паритета С1–С7») — единственный с дедлайном, но паритет не операционализирован. Владелец уже дважды за неделю зафиксировал ровно этот механизм смерти процессов (CLAUDE.md, история 18.08: «процессы не отменяются, а перестают запускаться»). §4 повторяет паттерн на уровне архитектуры.
**Mitigation**: строка в ADR: «ревизия триггеров §4 — календарная, раз в квартал, задача в панели; паритет С1–С7 — по чек-листу discovery §2». Триггер без календарной задачи — пожелание, не граница.

### F-2: Интерфейс Claude Code сменит поколение — обвязка обоих исходов стоит на недокументированном
**Severity**: high · **Type**: inertia / codebase aging · **Horizon**: 1–2 года, частично полгода

Контур привязан к текущему поколению headless-интерфейса: флаги `-p --resume --output-format stream-json`, формат `rate-limits.json`, файл `.credentials.json`, поведение OAuth. Половина — не контракт (форматы файлов — внутренности CLI), и интерфейс уже заметно менялся за 2025–2026. Разница исходов — *кто чинит*: в B смена флага — правка своего модуля за день; в A — ожидание апстрима yao либо форк их раннера, чужой код становится вашим в худший момент. Отдельно: находка S1b («молчаливый выход с кодом 0») через год при новом поколении CLI начнёт врать «сессия завершилась успешно», если обвязка не проверяет её явно.
**Mitigation**: интерфейс к CLI — отдельный модуль-прослойка в обоих исходах; проверка «креды читаемы, ответ не пуст» — в DoD Ф0, не только прозой в §5.

### F-3: Исход A — цена выхода из yao растёт со временем, путь выхода не зафиксирован
**Severity**: high (условно, только исход A) · **Type**: inertia / vendor lock-in · **Horizon**: необратимо к году 1–2

Решение честно называет асимметрию обратимости, но оценивает её на сегодня: «месяц» вытаскивания при двух неделях истории. Через 2 года в yao: история задач, workspaces-документы (заменившие vault!), диалоги песочниц, детекторы поверх недокументированного API. Цена выхода растёт линейно; «месяц» 2026-го — квартал 2028-го. Ф2-A предписывает перенос *в* yao, но нигде — обязательство обратного экспорта. Платформа к моменту смерти страховки становится безальтернативной не по качеству, а по стоимости выезда.
**Mitigation**: строка в Ф2-A: «с первого дня — регулярный дамп задач/документов/журнала из yao в свой формат (git-репо) — условие эксплуатации». Паттерн «база — истина, файлы — выгрузка» сохраняется, истиной временно назначен yao.

### F-4: Исход B — собственная инфраструктура стареет быстрее рабочих проектов, потому что всегда вторая в очереди
**Severity**: medium · **Type**: codebase aging / team · **Horizon**: год 1 заметно, год 2 определяет качество жизни

B на горизонте двух лет — 20–30k строк control plane, обслуживаемых в паузах между erp-ir и ir-gsm. Ловушка не в объёме, а в приоритете: инфраструктура координации всегда важна-но-не-срочна → дефекты класса AD-16 в ней норма. Через два года в B слой «знает только автор», причём авторы — Claude-сессии, чья память и есть предмет Ф3: циклическая зависимость (система памяти хранит знания о системе, которая её обслуживает).
**Mitigation**: норма в ADR: «дефекты панели класса „истина врёт" (статусы, доставка, устаревшая сборка) приоритетнее фич любых проектов»; триггер §4 №5 усилить по F-1.

### F-5: Второй человек-оператор ломает разные вещи в A и B — в B глубже, чем «пересмотр F7»
**Severity**: medium · **Type**: team / scale

В A мультипользовательность встроена — второй оператор почти бесплатен. В B всё спроектировано вокруг одного владельца: auth без ролей, журнал вопросов-владельцу без адресата. Дописывать роли в систему, два года прожившую с одним пользователем, — пересмотр схемы, не фича.
**Mitigation**: в схеме Ф2-B — поле «автор/адресат» у команд и ответов с первого дня, даже при одном значении. Миграция вместо перестройки.

### F-6: Отложенные решения §5 («уточняется при Document») — кандидаты в вечные времянки
**Severity**: medium · **Type**: adjacent decisions / inertia · **Horizon**: 6–18 месяцев

Supabase «пересматривается при переезде» — переезд будет гореть сроком, пересмотр не случится; через год панель на своём сервере ходит в eu-west-1 за каждым статусом. То же с двойной записью переходного периода: миграция без даты конца имеет свойство длиться; полтора хранилища — самое дорогое и самое липкое состояние, потому что работает.
**Mitigation**: у каждого «решается при Document» — дата/событие-дедлайн и умолчание («Supabase: до конца Ф2, по умолчанию — Postgres в compose»).

## Trend findings — speculative, with named signals

### F-7: Позиция Anthropic по подписочному headless формализуется в 1–2 года — в любую сторону
**Severity**: high при негативном исходе, вероятность средняя · **Confidence**: medium

Сигналы: Agent SDK намеренно принимает только `ANTHROPIC_API_KEY`; Managed Agents — только API-ключ; «сторонним продуктам нельзя claude.ai-логин без одобрения». Вектор последовательный: разделение «интерактивная подписка» ↔ «программное использование». Негативный исход бьёт по обоим мирам (C-Н1 рушится), но в B удар локализован в одном модуле, в A — проходит через чужую песочницу. Триггер в §4 есть, но пассивный (F-1): изменение ToS не приходит письмом.
**What would change my mind**: официальная документация, явно описывающая/запрещающая headless-подписку на серверах владельца; «подписочный» режим в Agent SDK.

### F-8: yao через 2 года — коммерциализация вероятнее смерти, и лицензионная «верификация» — рычаг
**Severity**: medium (только A) · **Confidence**: medium/low

Сигналы: 7,7k звёзд и 4,2k коммитов при 4 открытых issue (обсуждение в закрытых каналах); лицензия уже содержит инструменты монетизации (брендинг, «верификация сертификата», порог 50/$1M, одностороннее изменение); открытые источники описывают лицензию противоречиво («модифицированный Apache 2.0» vs «100% MIT») — сама неоднозначность есть сигнал незакреплённости. rc-темп — фаза захвата рынка; типичный следующий такт open-core на Go — free/enterprise-разделение (n8n, Grafana, MinIO). «Верификация» — компонент, чья работоспособность зависит от вендора: смена условий превращает её из формальности в выключатель. Персональный контур с двумя годами истории — худшая позиция для торга. Смерть проекта менее вероятна, чем его *китаизация* — апстрим формально жив, практически недосягаем; для оператора-одиночки эквивалент смерти.
**What would change my mind**: фиксация лицензии в OSI-форме + публичная дорожная карта к stable (доверие); «Enterprise Edition» с миграцией функций из free (ускоренный выход).

### F-9: Ниша «оркестрация headless CLI-агентов» созреет за 1–2 года — B станет legacy, и это приемлемо
**Severity**: low · **Confidence**: medium

Сигналы: DSH запущен стратегически с намерением довести до stable; Anthropic растит Agent SDK и Managed Agents; yao уже нативно стримит Claude Code. Три независимых игрока строят один слой — слой станет товаром. К 2028-му «свой spawn/resume-раннер на 20k строк» — как самодельный CI в 2020-м: работает, но с нуля так не начинают. Это «становится legacy», не «становится ошибкой»: тонкий B, чья ценность в схеме данных (журнал, детекторы, «done = состояние внешнего мира»), конвертируется в «наша модель задач поверх зрелой платформы» малой кровью; толстый B (песочницы, VNC, мультимодельность) — дорого. Граница «тонкий/толстый» — главное, что стоит охранять в исходе B.
**What would change my mind**: если через 12 месяцев ни DSH, ни преемники не дадут durable-интеграцию Claude Code с auth — ниша не созревает, B из «legacy» превращается в «единственное работающее», что оправдывает утолщение.

## What's likely to age well

Конструкция решения (тайм-бокс, бинарные SS, «неоднозначность = B»); Ф0 как принцип «доставка = владение процессом»; «done = состояние внешнего мира» + детекторы — самая переносимая интеллектуальная собственность контура; Postgres + append-only журнал + русский FTS — скучно и потому долговечно; резолюция П-1 — отказ, который не придётся отзывать.

## What's worth deciding now to defer pain

- F-1: квартальная календарная ревизия триггеров §4 задачей в панели + чек-лист паритета С1–С7.
- F-2: интерфейс к CLI — отдельная прослойка; проверка кредов — в DoD Ф0.
- F-3 (A): обратный экспорт из yao с первого дня.
- F-5 (B): поле «автор/адресат» в схеме сразу.
- F-6: каждому «решается при Document» — дедлайн и умолчание.
- F-9 (B): граница «тонкого» оркестратора — список того, что B не строит никогда.
