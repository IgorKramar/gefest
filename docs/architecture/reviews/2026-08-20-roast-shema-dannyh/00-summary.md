# Roast: shema-dannyh-decision (D-2)

**Roles run**: devil-advocate (B-N), pragmatist (H-N), junior-engineer (J-N), compliance-officer (C-N), futurist (F-N)

## Headline findings

- **Devil-advocate**: курсор `consumer_offsets.last_id` по глобальному bigserial молча теряет события при commit out-of-order — research назвал дыру и лечение, design лечение потерял; система лечит «недостоверные статусы» и воспроизводит их в своём канале (B-6).
- **Pragmatist**: «1.5–2 недели» — фулл-тайм, при 1–2 ч/день это 6–10 недель календаря с двойным учётом каждый день; деплой миграций под тремя ролями не специфицирован — первый день эксплуатации не спроектирован (H-1, H-5).
- **Junior-engineer**: GF-5 не существует среди GF-1…GF-4; «смоук-тесты обязательные» — три названия без процедуры; GENERATED-ключ от чужой таблицы — «не смог понять, как это работает» (J-1, J-2).
- **Compliance-officer**: сырые stream-json-файлы — клиентский контекст вне RLS, вне «удалить с производными», без прав ФС/шифрования/бэкап-решения; приватностный фильтр ADR-0003 по построению не накрывает саммари и вехи сессий (C-1, C-2).
- **Futurist**: допущение «писатель один» первым сломают свои же (cutover-скрипт, psql владельца), а не масштаб; часть Jira-дверей прорублена запрещённым же CHECK-паттерном (F-1, F-2).

## Cross-cutting concerns

- **CC-1. Конкурентность и восстановление** (B-1, B-2, B-3, H-4): CAS применить в каждом переходе (`WHERE revision=$n` + retry-протокол); lease на `taken` (таймаут по `taken_at`); reconciliation при старте бинаря (running-сессии без живого процесса → interrupted; протокол восстановления `version` при недописанном хвосте); легальный путь починки — `hef task fix-state` корректирующим событием (запрет без альтернативы не работает).
- **CC-2. Канал панели** (B-6): gap-detection в поллере — «ожидание пропуска с таймаутом» из research перенести в схему/протокол; альтернатива — курсор по xmin/committed-view.
- **CC-3. Исправления DDL** (B-4, J-«gave up», F-2): ключ задач — присвоение функцией при INSERT (`SELECT ... FOR UPDATE` счётчика), stored + UNIQUE, НЕ GENERATED; `projects.key` — иммутабелен (переименование — display-имя); `pools.kind` → lookup (симметрия с собственным анти-костылём №4).
- **CC-4. Trust-класс и MCP-интерим** (B-8, C-5): колонка происхождения/доверия в `task_events` (owner | agent | agent-от-недоверенного-контента) — дверь для D-16 сейчас, миграцией потом не открыть; интерим до D-16: MCP-запись — только статусы своей сессии, actor из контекста раннера (не из параметров), `assign` — только владельцу.
- **CC-5. ФС-контур сырья** (C-1, H-3, B-5): права ФС — только раннер; решение о шифровании каталога и попадании в бэкап — явное; janitor + деградация при ENOSPC + метрика диска; «удалить с производными» включает `raw_path`; `sessions.raw_state (present|rotated|deleted)`; переформулировать §3 decision — «потоки полны в пределах retention» + контракт саммари (F-3).
- **CC-6. Приватность сессий** (C-2): фильтр ADR-0003 распространяется на sessions/session_events по `project.scope_class` — в тот же fail-loud конфиг.
- **CC-7. RLS и аудит** (B-7, C-3, C-4, H-2): таблица `audit_log` — в эскиз (append-only, свои запреты, retention, old/new-решение); RLS-перечень: observations/tasks/commands-payload — расширить или явно принять «вне RLS до второго оператора»; psqlrc-хелпер владельца + тест «NULL-контекст → пусто, не всё»; границы аудита признать (спуфаемость set_config — аудит ловит честные ошибки, не злонамеренного владельца).
- **CC-8. Фазировка и деплой** (H-1, H-5, H-6, F-5): v1-ядро ~14 таблиц (список pragmatist), остальное — forward-миграциями с маркером «дверь, не активна» (+ ревизия RLS при активации); миграции — отдельный шаг `hef migrate` с DSN мигратора в compose; bootstrap-скрипт трёх ролей; календарная честность в ADR; «откат = restore pg_dump» — словами.
- **CC-9. Долгосрочные правила** (F-1, F-3, F-4, F-6, F-7, F-8): cutover-импорт — только через события `imported` бинаря, не прямой SQL; срабатывание аудит-триггера — алерт, не лог; «истина — Rust-enum, lookup — зеркало миграциями, runtime-INSERT запрещён»; перечисления доставки/сессий — «предварительные, D-4/D-5 правят forward-миграцией без пересмотра ADR»; семантика MCP-инструментов не срастается с транспортом (ревизии MCP ~2/год); PG18 не блокировать.
- **CC-10. Читаемость** (J-3…J-9): GF-5 завести; смоук-тесты — по строке сценария и признака провала; «дверь», «commit out-of-order», «RCE донора», `consumer_offsets` — определить; правило «vault/AD — истина» пометить как расширенное этим решением; пути входов в шапку.

## What survived

Выбор A не оспорен ни одной ролью. Futurist: «гибрид — скучный консенсусный паттерн, стареет достойно; предложение целиком не переинженерено». Устояли: журнал+state одной транзакцией, сырьё файлами/вехи в БД, RLS-каркас с v1, перечисления-не-строки, ключ партиционирования заранее, forward-only, UUIDv7 приложением, граница «агенты только через API/MCP», scope_class с первого дня.

## Recommended path

**Apply and proceed** — ни одна атака не бьёт по выбору альтернативы; все 39 находок закрываются редакцией 2 decision (исправления эскиза CC-1…CC-7, фазировка CC-8, правила CC-9, текст CC-10). Re-roast не требуется: правки корректируют эскиз внутри принятой архитектуры. Отдельного слова владельца заслуживают: (1) 70%-фазировка v1-ядра (меняет план GF-5); (2) интерим-ограничения MCP до D-16; (3) решение по бэкапу/шифрованию файлов сырья.
