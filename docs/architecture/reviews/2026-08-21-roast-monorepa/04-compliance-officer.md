# Compliance and security: monorepa-decision (D-17)

**Target**: docs/architecture/research/2026-08-21-monorepa-decision.md
**Date**: 2026-08-21
**Disclaimer**: не юрист; окончательные правовые оценки — за консультантом.

## Summary

Решение про раскладку и сборку, не про данные — регуляторная поверхность узкая: git-история приватного репо, контекст Docker-сборки, слои образов. Внутри неё решение согласовано с позами проекта; самая открытая брешь — перечень `.dockerignore` §1.7: при контексте от корня и сборке `deploy.sh` прямо на прод-VM он не исключает `.env`, `.git` и ключевые файлы — путь «секрет из корня → слой образа → GHA-кэш» не перекрыт.

## Applicable regulations and standards

152-ФЗ (данные на РФ-VM; репо/образы ПДн содержать не должны — раскладка обязана сохранять); Anthropic Consumer Terms (креды не в слоях `infra/executor-image/` и не в build-кэше); лицензии OSS (MIT/Apache/copyleft); GitHub ToS (видит код, `.sqlx`, workflow, GHA-кэш — принятая поза ADR-0012). GDPR/CCPA неприменимы (один владелец, нет внешних пользователей).

## Findings

### C-1: `.dockerignore` не исключает `.env`, `.git` и ключи при контексте от корня
**Category**: trust boundary · **Severity**: high

§1.7 называет только `target/`, `web/node_modules`, `web/dist`. Деплой ADR-0012 — `git pull && docker compose up -d --build` на РФ-VM: рабочий каталог прода традиционно держит `.env` с прод-DSN. Без `.env*`, `.git/`, `reference/`, ключевых масок — через широкий `COPY . .` секреты и вся история попадают в слои builder-стадии и в GHA-кэш (хранится у GitHub). **Закрывает**: расширенный перечень + правило «секреты сборки — только `--mount=type=secret`, никогда ARG/ENV».

### C-2: `.env`-дисциплина названа для CI, но не для git — граница «секрет в файле» не проведена
**Category**: retention / third-party risk · **Severity**: medium

§1.3 подталкивает локальную разработку держать `DATABASE_URL` в `.env`; `.gitignore` с `.env*` в составе первого PR не назван, правило «в `.env` — только локальный dev-DSN, ничего из матрицы секретов ADR-0010» не записано. Секрет в git-истории приватного репо остаётся навсегда. **Закрывает**: `.gitignore` с `.env*` в §6 (скелет) + фраза-граница.

### C-3: `.sqlx` раскрывает текст запросов и схему — соответствует позам проекта
**Category**: PII flow · **Severity**: low

`.sqlx` несёт SQL-текст и имена таблиц, включая клиентские скоупы; позы ADR-0003/0005 запрещают **содержимое** классов, не схему — DDL и так в `crates/db/migrations/` того же приватного репо. Новой поверхности нет; в slim-runtime не копируется. Остаточное: чувствительные литералы в SQL не хардкодятся (bind-параметры обеспечивают), фикстуры без реальных данных.

### C-4: Supply chain пинован выборочно — sqlx-cli назван, экшены GHA и остальное нет
**Category**: third-party risk · **Severity**: medium

Молчание: `Cargo.lock` в git (обязателен, не назван), точные версии в `mise.toml`, Bun, static-serve/cargo-chef/bacon, и главное — пин экшенов GitHub Actions по SHA (мутабельные теги — реальный вектор: CVE-2025-30066, tj-actions/changed-files, март 2025 — кража секретов CI через подменённый тег). В репо с агентами-коммиттерами воспроизводимость — защита ворот ADR-0012. **Закрывает**: строка «`Cargo.lock` в git; версии в `mise.toml` точные; экшены — по SHA».

### C-5: Лицензионная проверка не встроена в CI — при низком фактическом риске
**Category**: third-party risk · **Severity**: low

Стек чист (static-serve, cargo-chef — MIT/Apache-2.0; dev-инструменты не линкуются); self-hosted без распространения не создаёт обязательств даже при (A)GPL-транзитиве. Но транзитивный граф не проверяется, а «не распространяется» — поза, не конструкция. **Закрывает**: `cargo deny check licenses` в rust-job — одна строка; либо запись «аудит отложен до причины распространения».

### C-6: Образ исполнителя в общем репо — правило «в слоях нет кредов» не проговорено
**Category**: trust boundary · **Severity**: medium

§1.7 помещает `infra/executor-image/` в общий CI; установка CLI кредов не требует — хорошо. Но не сказано, где образ хранится (GHCR? локально на VM?), и не повторено правило: подписочные креды (`~/.claude`, OAuth) — ни в слои, ни в build-args, ни в кэш; только инжекция раннером в рантайме (ADR-0006). Запечённый кред — утечка и нарушение позы Consumer Terms разом. **Закрывает**: строка в ADR-0014 «образ собирается без кредов и секретных ARG; хранение — <названо>».

## What's well-handled

«env CI, не `.env`» — правильная сторона грабель sqlx#3836; `.sqlx`/миграции не создают поверхности сверх принятой; multistage не пускает исходники и toolchain в финальный образ; пин CLI исполнителя + контрактные тесты одним PR — supply-chain-дисциплина для самого рискованного компонента; один раннер задач — меньше мест оседания секретов.

## Areas I couldn't evaluate

Содержимое workflow (permissions `GITHUB_TOKEN`, пины экшенов) — файла нет, проверяемо с первого PR GF-5; лицензии транзитивного графа `web/` — до lockfile нечего читать; registry образов — не назван; изоляция GHA-кэша между ветками агентских PR — только на конкретном workflow.

Terminology pass: замен не потребовалось. Identifiers preserved.
