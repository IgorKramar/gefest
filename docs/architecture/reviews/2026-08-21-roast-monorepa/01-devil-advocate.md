# Devil's advocate: организация монорепы (D-17)

**Target**: docs/architecture/research/2026-08-21-monorepa-decision.md
**Date**: 2026-08-21

## Summary

Две сильнейшие атаки. Первая: `prepare --check` назначен «сторожем за агентами», но раскладка структурно лишает агента возможности перегенерировать `.sqlx` — в контейнере задачи нет Postgres с накатанной схемой Гефеста, любая задача, трогающая SQL, не доходит до зелёного PR честным путём. Вторая: path-фильтры §5 оставляют без единой CI-проверки корневой `Cargo.toml`/`Cargo.lock`, `.sqlx/**` и весь `infra/**` — включая бамп пина CLI, ради которого образ и положили в монорепу.

## Attacks

### B-1: Агент не может перегенерировать `.sqlx` — сторож сторожит дверь, через которую агент физически не проходит
**Type**: hidden assumption · **Severity**: high

Цепочка ADR: агенты — только PR (ADR-0012); контейнер задачи — без docker и секретов БД (ADR-0006). Компиляция `crates/db` с изменённым `query!` в offline падает; для prepare нужен живой мигрированный Postgres. Предсказуемое поведение агента в тупике: правка JSON в `.sqlx` руками, `SQLX_OFFLINE=true` в `.env` (ровно sqlx#3836) или уход на нетипизированный `sqlx::query` — эрозия главной гарантии. **Where**: §1 п.3, §5. *(Примечание агрегатора: комплект брокера ADR-0006 уже включает чистую dev-БД клоном шаблона — закрытие CC-1 строится на этом: шаблон со схемой Гефеста для задач над этим репо.)*

### B-2: Слепые зоны path-фильтров: корневой Cargo.toml, `.sqlx/**`, `infra/**` мержатся без CI
**Type**: edge case · **Severity**: high

Четыре фильтра §5 — закрытый список; решение само выносит версии в корневой `Cargo.toml` (вне `crates/**`): PR «бамп зависимости» проходит с нулём job-ов. То же `.sqlx/**` (разрешение конфликта после rebase) и `infra/**` (включая `mise.toml`, Dockerfile-ы). Усилитель: required-check, пропущенный по фильтру, у GitHub висит pending и блокирует чужие PR — либо фильтры ломают ворота, либо ворота не required и зоны мержатся молча. **Where**: §5; §1 п.2–3.

### B-3: Бамп пина CLI в `infra/executor-image/` не запускает контрактные тесты — ворота CC-8 ADR-0009 отсутствуют в конструкции
**Type**: logical inconsistency · **Severity**: high

Смысл размещения образа в монорепе — «один PR меняет пин и тесты вместе» (Q7); ADR-0009 требует зелёных контрактных тестов на обновление. Но рутинный PR «поднять пин» меняет только `infra/executor-image/**` и по §5 не запускает ничего. Требование живёт в прозе и памяти владельца, не в конструкции. **Where**: §1 п.7 против §5.

### B-4: Три несовместимые версии триггера контрактных тестов
**Type**: logical inconsistency · **Severity**: medium

§1 п.8: runner/fake-executor/тесты; §5: fake-executor выпал; ADR-0012: контрактные входят в rust-job на любой `crates/**` — отдельный contract-job либо дубль, либо молчаливая правка ADR-0012. И ни одна версия не включает `crates/core`, хотя правка типа в `core` меняет обе стороны контракта. **Where**: §1 п.8 ↔ §5 ↔ ADR-0012.

### B-5: У типов stream-json нет дома в графе — либо тавтологичный контракт, либо запрещённое ребро
**Type**: hidden assumption · **Severity**: medium

Типы в `core` + обе стороны на общих serde-типах → контракт вырождается в roundtrip собственных структур и не ловит расхождение с реальным CLI (кейсы ADR-0009 — невалидная JSONL, «exit 0 без result» — требуют побайтового контроля). Типы в `runner` → `fake-executor` не дотянется без запрещённого ребра (тащит tokio/sqlx в тестовый бинарь). Дублирование → дрейф без сторожа. Выбор определяет, чего стоят контрактные тесты, — документ молчит. **Where**: §1 п.1, п.8.

### B-6: «core без поведения и рантайма» несовместимо с «истина перечислений — Rust-enum» без затаскивания sqlx в core
**Type**: logical inconsistency · **Severity**: medium

Enum-ам из `core` нужны derive `sqlx::Type` для query-макросов `db`: (а) sqlx в `core` — «почти не пересобирается» умирает, `fake-executor` тянет sqlx; (б) зеркальные типы в `db` — дублирование без сторожа дрейфа. Где живёт derive — не сказано; вскроется первым PR GF-5. **Where**: §1 п.1 против ADR-0005.

### B-7: Компайл-тайм embed: Rust-сборка — заложница `web/dist`, а новые ассеты впервые встречают компилятор на прод-VM
**Type**: failure mode · **Severity**: medium

Прямо: rust-job на `crates/**` не собирает фронт → `api` падает на пустом dist на каждом backend-PR; лечение bun-шагом убивает path-разделение, заглушкой — громкий отказ. Обратно: web-only PR не компилирует `api` с новым dist → компайл-тайм обработка ассетов впервые случается на прод-VM при `deploy.sh` — зелёный CI, красный деплой. Плюс гонка: параллельность mise-задач (§1 п.6) при `build` без явного порядка bun→cargo вшивает полузаписанный dist. **Where**: §1 п.4, п.6, §5 + ADR-0012.

### B-8: Кэш нацелен на GHA, а единственный потребитель образа собирает на холодной прод-VM
**Type**: failure mode · **Severity**: medium

`type=gha` греет слои в CI, но деплой ADR-0012 — `--build` на РФ-VM: прогретое туда не доезжает; после любой правки корневого Cargo.toml (chef инвалидирует recipe — признано §3) VM пересобирает workspace + bun с нуля. VM минимальна (C-С1) и несёт прод-Postgres и раннер с живыми сессиями: линковка = OOM-kill сборки или CPU-голодание раннера в момент деплоя. Кэш спроектирован для builder-а, который образ никому не отдаёт. **Where**: §1 п.7 + ADR-0012 (деплой).

## Strongest single attack

**B-1**: проект существует ради агентов-коммиттеров — и принятая sqlx-схема требует того, чего у агента по периметру нет. Сторож ловит не забывчивость, а невозможность; агент выйдет нечестно (правка `.sqlx`, `.env`-флаг, нетипизированные запросы). Минимум до GF-5: назвать источник БД для prepare в контуре агента или регламент.

## Gaps in your own analysis

`mise.toml` ещё не написан — атаки на DAG задач велись по прозе (часть B-7 снимается одной строкой зависимости); топология dev-режима отсутствует — вопрос ясности, не мой; состав образа исполнителя (есть ли Rust-тулчейн) не зафиксирован — B-1 оценена по худшему прочтению; механику запуска `fake-executor` из `tests/contract` (CARGO_BIN_EXE между крейтами) не развернул — документ не фиксирует способ.
