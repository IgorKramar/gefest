# ADR-0006: Изоляция исполнителей — rootless-контейнер на задачу; Гефест — брокер ресурсов и секретов

- **Date**: 2026-08-20
- **Status**: Accepted
- **Authors**: Игорь (владелец); standard-цикл D-3
- Артефакты цикла: `../research/2026-08-20-izolyaciya-ispolnitelej{,-research,-design,-decision}.md`

## Context

Исполнители переезжают на сервер (C-Н2); сегодня изоляции между проектами нет, а roast D-2 (C-1) показал: файлы сырья читаемы любым процессом хоста, включая чужие claude-сессии. Владелец: изоляция **на каждую задачу**, жёстко; контекст не теряется; висящих не остаётся; лимиты с v1; общей dev-БД не будет — «чистая база» от Гефеста; docker исполнителю не нужен; **Гефест управляет распределением доступов, секретов и накопленных dev-сред** («чтобы по 10 раз не создавали одно и то же»). Research: bollard 0.21 — podman rootless first-class; сами вендоры (Claude Code `/sandbox`, Codex) используют bwrap-класс, но он собирается из трёх самодельных частей и не имеет нативных лимитов; template-клон Postgres — 10–40 мс; Ryuk-паттерн housekeeping. Кубер-мысль владельца оформлена уточнением триггера П-1: второй хост или нехватка ресурсов (пуш-бэк П-И1 принят).

## Decision

**Rootless-контейнер на задачу** под управлением раннера (bollard; podman предпочтителен, docker rootless допустим — выбор при GF-2):

- **Эфемерность и housekeeping:** контейнер живёт от старта до завершения задачи; labels `gefest.task_id`/`created_at`; reaper + TTL-sweep; реестр восстановим из labels после crash раннера. Контекст переживает песочницу: память роли — из канона, сессия резюмится, кандидаты памяти копируются при предложении.
- **Комплект брокера (prepare, идемпотентно по хэшу конфига):** worktree задачи; **чистая dev-БД клоном шаблона** (сериализованно, к шаблону нет подключений, `DROP WITH (FORCE)` при уборке); env выданных ресурсов из каталога (`resources`/`resource_grants` — волна 2 ADR-0005; выдача/отзыв — из панели, след автор/адресат); scoped git-токен; `~/.claude`-набор (креды подписки ro, память роли, hooks). **Секреты хранятся только у раннера, инжектятся в песочницу и умирают с ней; docker исполнителю не выдаётся.**
- **Изоляция и лимиты:** namespaces ФС/сеть/pid; том задачи — единственная видимая ФС; CPU/RAM-лимиты с v1 (cgroups v2; предпроверка systemd-делегирования cpu/cpuset — GF-2); общий канал агентов — только через Гефест (чат — D-9).
- **Сеть:** egress к Anthropic API, git-хостингам, MCP Гефеста; доменная прокси-фильтрация — D-7 (заимствование bwrap-пути).

## Consequences

**Положительные.** «Жёстко» одним зрелым механизмом; чужое сырьё/проекты недоступны по построению (закрывает C-1 roast D-2); лимиты и housekeeping нативны; контейнер → под дословно (мост к куберу по уточнённому триггеру); брокер убивает дублирование сред и расползание секретов.

**Отрицательные (приняты).** Свой образ исполнителя (Node+CLI) с конвейером обновления вслед CLI-релизам; прогрев cold-start; сокет рантайма у раннера (rootless смягчает, ограждение — D-7); сотни мс старта против мгновенного bwrap.

**Нейтральные.** bwrap-режим для лёгких задач — открытая дверь-оптимизация; выбор podman/docker — деталь реализации.

## Alternatives considered

- **B. bwrap + systemd-scope + свой прокси (путь Claude Code/Codex)** — легче и быстрее, доменная фильтрация в конструкции; отклонён: три самодельные части (свой прокси — постоянный компонент), лимиты вторым механизмом, известные обходы требуют allowlist-дисциплины, путь в поды — переписывание. Заимствованы: прокси-фильтрация (D-7), bwrap-дверь для лёгких задач.
- **C. Голые процессы + Unix-uid (статус-кво)** — отклонён: «жёстко» невыполнимо (общие netns/tmp/proc), C-1 остаётся.
- Не рассматривались: microVM (класс угроз не наш, F7), Kubernetes сейчас (П-1/П-И1), DinD (снят «чистой базой»), общий контейнер (не изоляция).
