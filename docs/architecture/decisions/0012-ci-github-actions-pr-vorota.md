# ADR-0012: CI — GitHub Actions с PR-воротами для кода; деплой ручным скриптом, CD — дверь

- **Date**: 2026-08-21
- **Status**: Accepted (amended in detail by ADR-0014: прод-образ собирает CI → GHCR, `deploy.sh` = pull, сборки на прод-VM нет)
- **Authors**: Игорь (владелец); light-цикл D-12
- Артефакты цикла: `../research/2026-08-21-ci-vorota{,-design}.md`

## Context

Правило decision-map: CI — до первого кода GF-2. Репо приватный на GitHub; коммиттеры — владелец и агенты (scoped-токены пула, ADR-0010). Состав проверок предопределён: Rust/sqlx (ADR-0004/0005), контрактные тесты против фальшивого исполнителя (ADR-0009), «готово = мерж + зелёная проверка» (доска задач). Владелец: PR-ворота для кода с правом прямого пуша доков; CD — дверь.

## Decision

- **GitHub Actions**, один workflow, job-ы по путям: `rust` (fmt → clippy `-D warnings` → test, включая контрактные против фальшивого исполнителя → `sqlx prepare --check`); `migrations` (Postgres service, `sqlx migrate run` на чистой БД, смоук + отрицательные RLS-тесты с NULL-контекстом); `front` (Bun: tsc, build). Кэш; таргет ≤ 5 мин.
- **Ворота:** main защищён — PR + зелёный CI + актуальная ветка. Агенты — только PR (их токены без права пуша в main — ворота усилены токеном). Владелец вправе пушить напрямую `docs/**`/`*.md`/hotfix.
- **Деплой:** ручной `deploy.sh` на РФ-VM (`git pull && docker compose up -d --build`), вызов через tailnet. CD (self-hosted runner) — дверь: триггер — деплой чаще N раз/нед или второй оператор.
  - *Уточнение к записи (не правка решения): механика деплоя изменена [ADR-0014](0014-monorepa-domennaya-shestyorka.md) — прод-образ собирает CI → приватный GHCR, `deploy.sh` = `compose pull && up -d`, сборки на прод-VM нет. Формулировка выше сохранена как исходная запись 2026-08-21; действует редакция ADR-0014. Дверь CD не затронута.*
- Контрактные тесты против **живого** CLI в CI не гоняются (жгут окно подписки) — только вручную при решении об обновлении CLI (ADR-0009).

## Consequences

**Положительные.** Ворота встают до первого кода; агентский вклад проходит одинаковый фильтр с токен-подкреплением; ноль новых резидентных сервисов (C-С1); docs-темп не замедлен.

**Отрицательные (приняты).** Прямой пуш владельца — дыра в воротах по определению (принята как право); ручной деплой — шаг руками; private-минуты GitHub — внешний лимит (при исчерпании — пересмотр).

## Alternatives considered

- **Всё через PR, включая доки** — отклонено: док-коммиты ждут CI без выгоды при одном операторе.
- **CD через self-hosted runner в tailnet** — отложено дверью: резидентный сервис против C-С1 и исполнение CI-кода рядом с продом; вернёмся по названному триггеру.
- Не рассматривались: сторонние CI-платформы (репо уже на GitHub, минут хватает).

## Review trail

Light-масштаб: roast пропущен (процессное решение, полностью обратимо правкой workflow). Ревью — по факту первых зелёных прогонов GF-5/GF-2.

2026-08-24 — **уточнение по факту реализации PR-1** ([план](../../plans/2026-08-24-001-feat-skelet-monorepy-plan.md)): ruleset на `main` заводится с **пустым bypass list** (решение владельца) — правила действуют и на владельца. Практическое следствие принято сознательно: послабление «доки владельца — напрямую» на практике не используется, владелец проводит через PR и документацию тоже. Разделять режимы на уровне ruleset сложнее, чем открыть PR. Состав ruleset — четыре правила, а не только проверки: require a pull request before merging; пять required status checks (`rust`, `front`, `migrations`, `contract`, `infra`); block force pushes; restrict deletions. Только required checks оставили бы прямой пуш открытым, и запрет из § Decision остался бы декларацией.
