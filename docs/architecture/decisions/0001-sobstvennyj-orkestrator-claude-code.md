# ADR-0001: Собственный тонкий оркестратор Claude Code-агентов вместо готовых платформ (yao, DSH)

- **Date**: 2026-08-20
- **Status**: Accepted (amended by ADR-0002: реализация — с нуля, не эволюция agent-dashboard)
- **Authors**: Игорь (владелец); deep-цикл `/architect:cycle`
- Артефакты цикла: discovery / research / design / decision (ред. 2) в `../research/2026-08-20-konsolidaciya-orkestracii-agentov*.md`

## Context

Команда Claude Code-агентов (4+ именных разработчика, ПМ; ~5–10 активных проектов; в пике 11 задач и 16 MR в день) координируется через три сменившихся за неделю поколения инструментов: vault Obsidian → agent-dashboard (Postgres/Starlette/React, «база — истина, файлы — выгрузка») → взгляд в сторону платформ DeepSeek Harness (DSH) и Yao Agents (yao). Боли, названные владельцем: недостоверные статусы; команды из панели не доходят до агентов (`sent` без подтверждения, гашение сессии выглядит завершением); нет доски задач; дублирование с Obsidian; управление из 7 терминалов вместо одной панели и одного сервера с доступом с телефона.

Жёсткие ограничения: исполнители остаются Claude Code на подписке Max 20x без API-токенов (C-Н1); один оператор (F7); один источник истины — общая система памяти, vault Obsidian выводится, привычки (wiki-линки, бэклинки, русский поиск) покрываются (C-Н5, С7); развёртывание — docker-compose, Kubernetes отложен до появления причины (П-1); полноценное управление с телефона.

Research (4 исследования + 3 практических спайка) установил:

- **DSH (v0.1.0-rc.8)**: штатный `subagent-claude-code` — one-shot без стрима, resume и видимости в Web UI; Claude Code не может быть членом `agent-team`; auth в Web UI отсутствует по дизайну (`--host 0.0.0.0` отклоняется). Как панель управления Claude Code — непригоден сегодня; ядро уже растит интеграцию Claude Code (rc.7/rc.8).
- **yao**: единственная готовая платформа со стримингом и resume Claude Code (stream-json, персистентные Docker-песочницы), но rc каждые 1–3 дня, лицензия с несъёмным брендингом и «логикой верификации», API доски не документирован.
- **Спайки**: подписочный OAuth работает в контейнере (S1a) и в yao-образе (S1b, с ловушкой «CLI молча выходит с кодом 0 при нечитаемых кредах»); параллельные headless-сессии работают, лимиты читаются (S2).
- **Consumer Terms Anthropic (первоисточник, проверен после roast-находки C-1)**: креды аккаунта нельзя делать доступными другим (§2); автоматизированный доступ — только через API-ключ или где явно разрешено (§3). Headless `claude -p` — официальная функция Claude Code → собственный раннер, вызывающий официальный CLI на машине владельца, аргументируем; монтирование подписочных кредов в песочницу стороннего продукта (yao) — запрещённый случай с ценой «бан аккаунта = остановка всех исполнителей».

Ранняя редакция решения (композиция: B-основа + недельный пилот yao с воротами) прошла адверсариальный roast (5 ролей, 40 находок) и была пересмотрена: пилот отменён по договорному основанию. Владелец выбрал исход B с формулировкой: «мы внимательно изучаем yao и dsh, как они устроены, чтобы построить свою систему на их плечах; текущая панель делалась на ходу из потребности, без архитектуры и ориентиров — теперь подойдём с умом».

## Decision

Строим **собственный тонкий оркестратор** — эволюцию agent-dashboard до полноценного управляющего контура (control plane) команды Claude Code-агентов, проектируя его по архитектурным образцам yao и DSH (заимствуем решения, не код и не зависимости).

1. **Ф0 (немедленно, бюджет 2 недели):** доставка команд через владение процессом — раннер порождает и возобновляет `claude -p --resume` (stream-json); состояние `delivered` подтверждаемо; идемпотентность по ключу задачи; переподхват живых сессий при рестарте раннера; плюс три страховки: health-check кредов (ловушка S1b), внешний heartbeat, pg_dump по крону с одной проверкой restore.
2. **Ф0.5 (архитектурная):** карта заимствований из yao/DSH → ARCHITECTURE.md целевой системы + ADR-серия (модель сессий/журнала, модель доставки, прослойка CLI, схема данных, периметр). Кандидаты заимствований: append-only session log как единственная истина (DSH), stream-парсинг и resume-механика (yao `agent/sandbox/v2/claude/`), DAG задач с CAS-ревизиями и mailbox (DSH `agent-team`), машина состояний доставки.
3. **Далее:** Ф1 — серверный контур (compose, VPN-периметр, доска-UI, матрица секретов, вывод из Supabase); Ф2 — паритет по чек-листу С1–С7 (стриминговый просмотр, wiki-слой, PWA); Ф3 — канон памяти с двусторонним согласованием личных памятей.

Принципы, принятые вместе с решением:

- **Панель не смотрит в публичный интернет** — доступ только через VPN/mesh; публичный endpoint — только отдельным решением с компенсациями.
- **Прослойка CLI**: всё общение с Claude Code (флаги, stream-json, форматы `~/.claude`) — один свой модуль; смена поколения CLI — правка одного модуля.
- **Граница «тонкого» оркестратора**: не строим никогда (без отдельного ADR) — собственные VNC/desktop-песочницы, мультимодельных агентов-исполнителей, чат-клиент общего назначения, собственный CI.
- **Норма обслуживания**: дефекты класса «истина врёт» (статусы, доставка, устаревшая сборка) приоритетнее новых функций любых проектов.
- **Активные границы пересмотра**: квартальная календарная задача ревизии триггеров (DSH дозрел; yao легализовался; Anthropic формализовал запрет; второй оператор; причина для кубера; 3 месяца без паритета — ревизия с явными исходами).
- **Аудит**: журнал команд append-only, действия владельца и агентов различимы; retention диалогов — до включения их долговечности.
- **Схема данных** готовится ко второму оператору заранее: поле автор/адресат у команд и ответов с первого дня.

## Consequences

**Положительные.** Единственный путь, гарантированно совместимый с подпиской Max (примитивы — официальные функции Claude Code); процесс команды (`/ir-task`, worktrees, «готово = мерж + зелёный пайплайн», детекторы расхождений) сохраняется без адаптации; полный контроль периметра; дешёвая конвертация в «наша модель задач поверх зрелой платформы», когда рынок дозреет (перенос — схема данных и журнал, не UI).

**Отрицательные (приняты).** 4–7 недель чистой разработки до паритета (календарно 2–4 месяца при темпе «между основными задачами»); bus-factor 1 (весь контур держится на одном человеке); отказ от бонусов платформ (VNC-песочницы, готовые клиенты); собственная инфраструктура всегда вторая в очереди — компенсируется нормой обслуживания и активными ревизиями; остаточный ToS-риск серверного подписочного headless принят владельцем.

**Нейтральные.** Клоны yao/DSH остаются в `reference/` учебным материалом; знания об их устройстве (docs/03–04, 06) — актив для границы пересмотра №1–2; vault выводится только после проверенного restore, git-выгрузка живёт до этого дня.

## Alternatives considered

- **A. yao как платформа** — единственная готовая со стримингом/resume Claude Code; отклонена: подписочные креды в стороннем продукте запрещены Consumer Terms (без них — API-токены против C-Н1 либо не-Claude исполнители против ответа №1); плюс rc-темп 1–3 дня, лицензия с «логикой верификации», недокументированный API доски. Возврат — через границу пересмотра №2.
- **C. DSH как платформа (отложенная ставка)** — отклонена: сегодня исполнитель невидим и невозобновляем (one-shot), auth отсутствует по дизайну, срок зрелости вне нашего контроля. Возврат — через границу №1.
- **D. Статус-кво** — отклонена: все названные боли сохраняются, C-Н5 недостижим.
- **E. Композиция «B-основа + недельный пилот A с воротами»** (ред. 1 решения) — отклонена после roast: пилот проверял бы то, чем нельзя пользоваться (кластер 1); вдобавок пилот был слеп к расхождениям (три источника истины, детекторы не видят yao) и субъективен в вердиктах (кластеры 2).
- Ранее отклонены на design: Kubernetes сейчас (П-1), миграция исполнителей на другие модели, Agent SDK/Managed Agents (только API-ключ), SaaS-оркестраторы (приватность, авторство), dsh-crew (обратное направление), DSH agent-team как ростер для Claude Code (технически невозможно — `prepareContinuable`).
