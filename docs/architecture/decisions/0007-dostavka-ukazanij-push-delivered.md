# ADR-0007: Доставка указаний — push раннером в stdin, каузальный delivered, stop = SIGTERM

- **Date**: 2026-08-21
- **Status**: Accepted
- **Authors**: Игорь (владелец); deep-цикл D-4
- Артефакты цикла: `../research/2026-08-20-model-dostavki{,-research,-design,-decision}.md`; roast — `../reviews/2026-08-20-roast-model-dostavki/00-summary.md`

## Context

Боль №2 консолидации — «команда отправлена, агент её не увидел»: у agent-dashboard нет разницы между «записали» и «дошло». Исполнители — headless Claude Code на подписке (C-С1: биллинг по активности ресурсов, токены на подтверждения не жжём). Спайки собственным исполнением: S3 — stdin живого процесса принимает сообщения между ходами; S4 — mid-turn-запись ложится в очередь CLI и доставляется на границе шага; S5 — очередь >1 FIFO, склейка в одно продолжение, `num_turns` не годится как каузальный маркер per-сообщение — годится активность потока после `tool_result` инструмента, in-flight на момент записи. Roast (5 ролей, 36 находок, 13 high): выбор не оспорен, вердикт «Apply and proceed»; центральные правки — каузальный delivered (CC-1), инвалидация очереди стопом (CC-2), сон без остановки контейнера в v1 (CC-3), приватность текста указаний (CC-6), фазировка GF-2 (CC-9). Три упрощения v1 подтверждены владельцем 2026-08-21.

## Decision

**Push раннером + delivered-по-потоку + `requires_ack`-дверь** (альтернатива A design):

- **Транспорт:** раннер владеет stdin каждого живого исполнителя; writer per-сессия сериализует запись и SIGTERM (EPIPE → возврат в `queued`). Истина — в таблицах (ADR-0005), stdin — только транспорт.
- **Состояния:** `queued` → `sent` → `delivered` → терминальные исходы в `command_deliveries` (append-only). **Delivered каузальный:** запись в простое — по началу новой активности; mid-turn — только по активности после `tool_result` in-flight-инструмента; error-события не подтверждают; таймаут наблюдателя — настройка. **Reconciliation:** всё `sent` без каузального delivered умершего процесса → `queued` («дублируем, не теряем»); дедуп раннером по uuid в живую сессию; at-least-once — потолок.
- **Stop:** SIGTERM (exit 143, сессия сохраняется, resume возможен); раннер синтетически закрывает ход в вехах (`interrupted`); **stop инвалидирует очередь** — `queued`/`sent`-без-delivered → `cancelled_by_stop`. В вехах и UI «стоп» — класс прерываний, SIGTERM — реализация.
- **Сон:** блокирующий вопрос → `waiting_answer`, вопрос — событие session_events; **v1 без остановки контейнера** (спящий = живой процесс, reaper знает `sleeping`); стоп-по-таймауту — код за флагом (>2 спящих), двухфазный барьер `stopping` → `sleeping_cold` исключает гонку «ответ во время остановки».
- **Планировщик v1:** глобальный потолок 5 + 1 ручной слот владельца (per-operator настройка), FIFO; поле «почему стоит» (`quota`/`limit`/`probe`/`sleeping`) и лог решений — с первого дня. Лимиты — двухосевая политика (5h + weekly, оси — конфиг): `system/api_retry` → пауза до `resets_at`, fallback — экспоненциальная проба (5 мин ×2 до 60 мин); ручной слот минует паузу окна, при жёстком отказе — `limit_blocked` + уведомление; метрика голодания фона — в панели. Из api_retry-вех в БД — белый список полей, остальное — raw-файл вне БД.
- **Ретраи v1:** один авто-ретрай чистым рестартом → `paused` + инцидент; перед ретраем — сверка вех («сделано?» → не ретраить, вопрос владельцу); side-effect слепо не ретраятся. Типология сбоев и до 3 ретраев с resume — итерация 2.
- **`requires_ack`:** в v1 — только решение, кода нет; **бюджет: >2 классов с ack = пересмотр D-4.**
- **Приватность:** текст указания — носитель клиентских данных: scope_class на таблицах инбокса, retention тела 90 дней (факт — вечно), «удалить с производными» включает тексты, алерты — факт+ссылка без свободного текста, opt-out «Improve Claude» — предусловие эксплуатации; auth ручного слота и недостижимость owner-эндпоинтов из сети исполнителей — D-7.
- **Единый инбокс:** `command` ≠ `message` в перечислении с v1; `message` лежит `queued` до естественного пробуждения без эскалации — задел D-9.

## Consequences

**Положительные.** Боль №2 закрыта наблюдаемой механикой без токенов и без дисциплины модели; стоп с инвалидацией очереди — управляемое прерывание, не «доиграй потом»; сон бесплатен по токенам и дешёв по коду; фазировка честная — ядро 4–6 недель (полный объём 60–100 ч признан до старта).

**Отрицательные (приняты).** `delivered` — свидетельство реакции потока, не понимания (смягчение — дверь); interrupt внутри tool-вызова невозможен; поведение CLI — снимок, не контракт: S3/S4/S5 становятся контрактными тестами прослойки CLI (вход D-6), версия CLI пинуется; остаточный дубль в новую сессию после рестарта; транскрипты с uuid у Anthropic — размен «форензика > нелинкуемость».

**Нейтральные.** Приоритетная сортировка, пер-ролевые квоты, типология ретраев, стоп-по-таймауту, requires_ack-код — итерация 2 по данным панели; всё покрыто правом forward-миграции ADR-0005.

## Alternatives considered

- **B. Pull исполнителем (MCP-инструмент «проверь инбокс»)** — отклонён: подтверждение зависит от дисциплины модели (конституционное недоверие), жжёт токены на опрос, спящий не опрашивает.
- **C. Push + обязательный ack** — отклонён как общий режим: каждый ack — токены и задержка; оставлен дверью `requires_ack` с бюджетом.
- **D. Внешняя шина (сокет/файл-очередь в контейнере)** — отклонён: второй канал в обход раннера, периметр D-7 дырявится, доставка-по-сокету — антипаттерн ARCHITECTURE.md.
