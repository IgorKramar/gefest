# ADR-0003: Канон памяти — в Postgres Гефеста; pgvector — дверь с включением по замеру; EverOS — донор идей, не зависимость

- **Date**: 2026-08-20
- **Status**: Accepted
- **Authors**: Игорь (владелец); deep-цикл `/architect:cycle` (D-8)
- Артефакты цикла: `../research/2026-08-20-kanon-pamyati*.md` (discovery 2 раунда / research / design / decision ред. 2)

## Context

Память команды Claude Code-агентов размазана по шести слоям с разными хозяевами (авто-память по cwd, CLAUDE.md-слои, база знаний vault, дневники .remember, documents в agent-dashboard, learnings-процесс): память worktree умирает с worktree, база знаний дублируется трёхслойно, инжекция «всё в каждый старт» упирается в токены. Требование владельца C-Н5: один источник истины — общая система памяти; личные памяти согласуются; vault выводится; привычки покрываются (С7). Уточнения владельца в цикле: скоуп — «полный фарш» (знания, карточки, дневники, память ролей; оперативные задачи/борды — территория D-2); память ролей переносима между worktree и машинами (C-П2); редактор канона — сам владелец через панель («поручать мастер-агенту — увеличит расход, лучше я сам»).

Research: EverOS (12,2k ⭐, markdown-first память) отклонён как зависимость тремя блокерами, каждого достаточно: (1) русский поиск мёртв в бесплатном режиме — токенизатор jieba режет кириллицу посимвольно, BM25-колонка пуста (подтверждено исполнением); (2) стек SQLite+LanceDB архитектурен, Postgres невозможен, один процесс на root, общей командной памяти нет; (3) интеграции с Claude Code нет (официальный плагин — легаси чужого облака). Русский FTS в Postgres эксплуатационно доказан (agent-dashboard). Roast (5 ролей, 38 находок: 13 high) не оспорил выбор, но закрыл обвязку: неизмеримый триггер, бюджеты инжекции, мост «роль → cwd», приватность фоновых задач, retention — все кластеры CC-1…CC-8 применены в decision ред. 2.

## Decision

Канон знаний и памяти — **таблицы Postgres Гефеста** рядом с оперативным каноном (D-2): скоупы (глобальный/проект/роль), классы (правило, ловушка, learning, справочник, карточка, журнал), ревизии, автор, русский FTS, связи для wiki-линков/бэклинков, вес класса в recall-выдаче.

Ключевые механизмы (полные формулировки — decision ред. 2):

1. **Трёхслойный recall (Р-1) с бюджетами:** ядро ≤ 12 КБ и индекс ≤ 16 КБ инжектятся в старт сессии (превышение — громкое падение генератора, приём в полное ядро требует вытеснения решением владельца); тело — recall-by-need через MCP/CLI **с авторизацией по скоупу**; классы «карточка»/«журнал» — вне индекс-инжекции.
2. **Подъём:** хук конца сессии копирует сырьё кандидата в таблицу в момент предложения (+ скан осиротевших memory-каталогов для аварийных сессий); **редактор — владелец** через панель (список: принять/отклонить/править), алерт на очередь; редакционная политика — сама запись канона. LLM-редактор исключён (стоимость + blast radius ядра).
3. **Выгрузка вниз:** генератор производных файлов (ядро+индекс для SessionStart; memory-файлы роли по cwd — вторым шагом) — через прослойку CLI (мандат расширен на форматы `~/.claude`), с маркером и ревизией канона в шапке, детектором дрейфа, генерацией по worktree-хуку и громким падением при смене структуры каталога harness.
4. **pgvector — дверь:** расширение установлено, таблица `memory_embeddings (entry_id, model, dim, vector)`, до включения размерность не зафиксирована. Включение = фиксация размерности + backfill + построение индекса; смена модели после включения = повторный embed (цена признана). Триггер — наблюдаемый замер: промах = пустой ответ ИЛИ `miss=true` от агента ИЛИ повторный запрос с перекрывающимися термами ≤ 10 мин; доля промахов > 10% за скользящие 7 дней; отчёт — пункт квартальной ревизии GF-4.
5. **Приватность правилом:** классы «карточка»/«журнал» и клиентские скоупы не покидают Postgres ни одной фоновой LLM-задачей (фильтр — fail-loud конфиг); остальное — opt-in на бесплатном OpenRouter. Recall-лог — метаданные без тел, retention 6 месяцев.
6. **Retention/переносимость:** операция «удалить с производными»; штатный автоматический файловый экспорт канона (md+frontmatter, поэнтрийно, self-hosted, чувствительные классы по флагу) с проверенным restore.
7. **Переходный период:** vault — истина до дня переключения SessionStart-хуков; в этот день — заморозка vault на запись; перед выводом — сверка контента; предусловие переключения — рабочий CLI create/edit/list.

## Consequences

**Положительные.** Один источник истины буквально — память в той же СУБД, что задачи и журнал; ноль новых сервисов (F7); русский поиск доказан; память ролей переносима; редакционный контур дешёв и человечен; приватность и бюджеты — правилами, не дисциплиной.

**Отрицательные (приняты).** Правка знаний — панель/CLI, не Obsidian (смягчение — файловый экспорт); git-истории знаний нет (ревизии в БД + экспорт); векторный recall не с первого дня; редакционная нагрузка на владельце (~2–4 ч/нед батчем); мост «роль → cwd» — своя механика на движущейся стороне harness; миграция — скрипт за дни плюс редакционный проход 1–2 недели (ядро формируется выжимкой, не переносом).

**Нейтральные.** EverOS остаётся донором идей (entry-id, поэнтрийная переиндексация, durable-очередь, fail-loud конфиг, цикл recall→capture→flush); клон в `reference/everos`; разбор — research-дайджест цикла.

## Alternatives considered

- **B. Md-файлы в git как истина + производный Postgres-индекс** — отклонена: каскад «файлы↔индекс» — свой мини-EverOS с вечным классом «два состояния под одним видом»; два класса истины против духа C-Н5; конкурентные правки панели и агентов = git-конфликты в рантайме. Привычка «править файлы» покрывается экспортом.
- **C. EverOS как сервис** — отклонена тремя блокерами (см. Context); условие владельца «готов, если того стоит» не выполнено: не экономит ни обвязку, ни поиск, ни эксплуатацию. Возврат — граница пересмотра 4.3.
- **D. Статус-кво (шесть слоёв)** — отклонена: C-Н5 нарушен по построению, память ролей непереносима, vault не выводится.
- Отклонены на design без полной проработки: графовые/векторные памяти экосистемы DSH (README-зрелость), облачные memory-сервисы (приватность), отдельная СУБД под память (F7), полностью автоматический подъём (решение владельца — гибрид, ред. 2 — владелец-редактор).
