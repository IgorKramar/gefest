# Discovery: периметр, секреты и брокер ресурсов (D-7)

- Дата: 2026-08-21 · Масштаб: standard · Входы: O-5/GF-1.5; ADR-0006 (комплект брокера, «секреты только у раннера», делегирование прокси-фильтрации); ADR-0007 CC-7 (auth ручного слота, owner-эндпоинты недостижимы из сети исполнителей), C-2 (opt-out «Improve Claude» — предусловие), C-3 (алерты без свободного текста — канал не назван)

## Problem

Последнее решение серии GF-1: чем защищён вход владельца (панель, телефон), как агенты аутентифицируются в MCP Гефеста, где физически живут секреты раннера, как выдаются scoped git-токены, что такое «ресурс» в каталоге брокера и что исполнителям разрешено наружу.

## Forces

- Один оператор (F7): всё, что требует ручного обслуживания чаще раза в квартал, — не жилец.
- C-С1: биллинг по ресурсам — внешний Vault-класс (резидентный сервис) дорог и избыточен.
- Конституция: секреты не живут у агентов (ADR-0006); панель не в публичном интернете; аудит различает владельца и агентов (ARCHITECTURE.md).
- Roast D-4 C-4: VPN — сетевой слой, «любое устройство в mesh = владелец» — не аутентификация; actor_id должен назначаться механизмом, названным явно.
- Исполнители имеют egress к Anthropic/git/MCP Гефеста (ADR-0006) — сеть исполнителей не должна дотягиваться до owner-поверхности.
- Телефон — полноправный пункт управления (C-Н4 discovery консолидации).
- Каталог ресурсов: `resources`/`resource_grants` — волна 2 схемы (ADR-0005), выдача/отзыв из панели, след автор/адресат.

## Existing constraints

Хост — тот же, где AFFiNE (умолчание до Ф1); compose; Rust-бинарь один (axum) — слушатели дёшевы; GitHub и GitLab оба в игре (детекторы D-11); бэкап pg_dump вне хоста (шифрование не оговорено).

## Open questions (владельцу)

- **Q1. Сеть владельца — что уже есть фактом?** Какой VPN/mesh сейчас — WireGuard вручную, Tailscale/Headscale, что-то ещё? Телефон уже в нём? (Решение строится вокруг существующего, а не выдумывает новый слой.)
- **Q2. Аутентификация панели поверх VPN:** (а) сессионная (логин+пароль владельца, сессионная кука, срок — недели) — второй фактор не нужен, VPN уже первый; (б) passkey/WebAuthn — телефон и ноутбук как ключи, без пароля; (в) mTLS-клиентские сертификаты. Что удобнее жить с телефона?
- **Q3. Хранилище секретов раннера:** (а) age/sops-файл на хосте (0600, ключ у владельца, версии в приватном git) — просто, ручная ротация; (б) секреты в Postgres под pgcrypto (выдача через брокер, аудит выдач в БД); (в) внешний менеджер (Vault/Infisical) — против C-С1/F7. Куда склоняешься и есть ли секреты, которые в БД класть нельзя вообще (например, ключ бэкапа)?
- **Q4. Git-токены:** выдавать per-task автоматически через API хостинга (fine-grained/project token, TTL — жизнь задачи) или пул заранее созданных вручную scoped-токенов, который брокер только раздаёт? Автовыдача = токен API с правом создавать токены у раннера (концентрация привилегии).
- **Q5. Что есть «ресурс» каталога:** только комплекты кредов/env (ключи API, DSN) — или тоже живые сервисы (поднятая dev-БД, S3-бакет, тестовый аккаунт)? Создаёт ресурсы только владелец, или агент может предложить (владелец подтверждает — по образцу памяти ADR-0003)?
- **Q6. Egress исполнителей v1:** жёсткий allowlist доменов сразу (Anthropic, git-хосты, MCP Гефеста, — прокси из ADR-0006-заимствования) — или в v1 без фильтра (изоляция контейнером), allowlist — дверь по первому инциденту?
- **Q7. Канал алертов (C-3):** каким каналом владельца догонять вне панели — Telegram-бот, push (ntfy), почта? Канал получит только «факт+ссылка», но сам канал надо назвать и завести.

## Ответы владельца (2026-08-21)

- **Вводная сверх вопросов:** Гефест — на **отдельном хосте** у российского облачного провайдера (подбор провайдера — в этот цикл; умолчание O-4 «тот же хост, где AFFiNE» снято).
- Q1: Tailscale, настраиваем с нуля; телефон — в tailnet. **Уточнение владельца:** координатор — свой (Headscale-класс, self-hosted control server); у владельца уже есть опыт такой настройки. Зависимость от облака Tailscale снимается.
- Q2: mTLS — «выпустим сертификаты».
- Q3: (б) — секреты в Postgres под pgcrypto, выдача через брокер, аудит выдач в БД.
- Q4: пул заранее созданных вручную scoped-токенов; Гефест следит за остатком и просит владельца пополнить, когда не хватает.
- Q5: ресурсы — и креды/env, и живые сервисы; агент может предложить ресурс, владелец подтверждает (образец — кандидаты памяти ADR-0003).
- Q6: egress-фильтр — дверь по первому инциденту; v1 без доменного фильтра (изоляция контейнером).
- Q7: каналы алертов — все три (Telegram, push/ntfy, почта); содержимое — только факт+ссылка (C-3).

## Success criteria

Владелец с телефона управляет всем через названный механизм auth; агент не может достучаться до owner-эндпоинтов и чужих секретов по построению; каждый секрет имеет носителя, политику ротации и след выдачи; GF-2/GF-3 могут реализовывать без новых решений.
