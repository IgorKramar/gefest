# Decision summary: прослойка CLI (D-6)

- Дата: 2026-08-21 · Фаза: Decide (light) · Входы: discovery (Q1–Q2), design
- Статус: **принято владельцем** («1 - a, 2 - a», 2026-08-21). Roast на light не проводится.

## Выбранное

1. **Идентификатор сессии (Q1-а):** строка sessions создаётся транзакцией до старта процесса; `--session-id` = её UUIDv7; после рестарта раннера — `--resume` тем же UUID. Флаг continuation — выводим из состояния строки (KV-стор yao не нужен). Ретрай → новая строка/UUID с `parent_session_id` (ADR-0008).
2. **Reasoning (Q2-а):** `thinking_delta` пишется в сырьё и виден в drill-down; вех на reasoning нет.
3. **Пакет заимствований yao** (docs/06 §1): heredoc + промпт файлом; флаги stream-json; stderr — информация; невалидный JSON — continue; дренаж строк > лимита; «exit 0 без result + stderr» = setup failed → ретрай-путь ADR-0007; **SIGKILL после финального `result`** (зависание stream-json-режима; дети умирают с контейнером задачи — приемлемо по ADR-0006); `parent_tool_use_id` → дерево саб-агентов в вехах; MEMORY.md не перезаписывается. Не взято: игнорирование thinking, белый список из трёх флагов, suspend/resume групп.
4. **Контракт прослойки:** S3/S4/S5 — исполняемые контрактные тесты против фальшивого исполнителя и (по решению об обновлении) против живого CLI; версия CLI пинуется в образе исполнителя (ADR-0006), обновление образа = прогон контрактных тестов (ADR-0007 CC-8).

## Почему

Донор проверен в бою (807-строчный парсер yao — карта граблей); единственная развилка — схема ID — решается в пользу уже существующей системы идентификаторов ADR-0005: UUIDv5-функция у yao компенсировала отсутствие таблицы сессий, у Гефеста таблица есть, «восстановление без БД» — пустой сценарий.

## Что отдаём

Зависимость от недокументированного поведения CLI остаётся (смягчение — контрактные тесты + пин); SIGKILL финального процесса убивает его детей — в модели контейнер-на-задачу это уборка, не потеря; лимит строки/heartbeat — константы GF-2, меняются без пересмотра.

## Операционные последствия

GF-2: модуль прослойки (запуск/флаги/парсер/завершение) + фальшивый исполнитель уже в ядре v1 (ADR-0007 §5); контрактные тесты — в CI (D-12). Перечисления вех/состояний — уже в GF-5.

## Границы пересмотра

Смена поколения CLI (падение контрактных тестов) → ревизия прослойки решением; появление документированного протокола управления (interrupt и т.п.) → расширение прослойки (граница ADR-0007); нужда в reasoning-вехах из практики наблюдения → пересмотр Q2 forward-миграцией.
