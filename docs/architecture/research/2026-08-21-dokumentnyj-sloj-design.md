# Design: документный слой (D-10)

- Дата: 2026-08-21 · Масштаб: standard · Входы: discovery (Q1–Q6 + ответы), research digest

## Общая часть (инвариантна к альтернативам)

- **Хранение:** документы в Postgres (markdown-текст + метаданные); история правок — поток событий по конституции ADR-0005 (Q2-а), восстановление версий; CAS на текущей версии; scope_class и RLS действуют.
- **Линки:** [[wiki-линки]] парсятся при сохранении в таблицу `links` (источник, цель, битая/живая — «два состояния под одним видом»); бэклинки и граф — запросы по ней; русский FTS — хранимый tsvector (ADR-0005).
- **Записи агентов (Q3-а):** рабочие документы задачи — свободно; общий канон — предложение → подтверждение владельца (четвёртое применение механики pending).
- **Кнопка «в память» (Q6):** выделение → кандидат карточки канона (контур ADR-0003, подтверждение владельца).
- **Импорт vault (Q5):** выборочный, разделами; битые [[линки]] помечаются, не теряются.
- **Периодические заметки (Q1):** daily/weekly/monthly — документы по шаблону с автосозданием при открытии; шаблоны — обычные документы-заготовки.
- **Виды (dataview-класс, по research):** DQL не тащим; `saved_views` = JSON-спека (фильтры тег/дата/линки, сортировка, колонки, layout) → параметризованный построитель SQL в axum; вид встраивается в документ fenced-блоком ` ```view `; аварийный люк — сохранённые raw-SQL под read-only ролью, только владельцу. Computed-поля в спеку не добавляются (граница против ползучего DSL).

## Альтернативы (редакторная основа + фазировка)

**A. CodeMirror 6 через Atomic Editor + фазировка v1/v2.** Редактор — `@atomic-editor/editor` (reveal у курсора, [[автодополнение]], подсветка — из коробки; MIT, форк-план Б при смерти проекта; предусловие — ручная проверка на телефоне и React 19 Strict Mode). **v1:** линки+бэклинки, FTS, периодические заметки, теги, шаблоны, подсветка, история, «в память», выборочный импорт, виды-JSON без GUI-конструктора. **Итерация 2:** граф связей, GUI-конструктор видов (Bases-паттерн), raw-SQL-люк.

**B. Своя сборка на CodeMirror 6.** То же поведение, полный контроль, ноль зависимости от bus-factor-1-проекта; цена — ядро 1–2 недели + хвост (таблицы, embed, IME) в месяцы; референсы открыты (Atomic, codemirror-live-markdown, Joplin Rich Markdown).

**C. Статус-кво: остаться на Obsidian vault.** Ноль работы; но один источник истины не достигается (C-Н5), агенты не читают vault через Гефест, ADR-0002 нарушен — отвергается целью.

| Критерий | A: Atomic Editor | B: своя CM6-сборка | C: vault |
|---|---|---|---|
| Reveal у курсора (ТЗ Q4) | Из коробки | Пишется руками | Родной |
| Срок до рабочего редактора | Дни (интеграция+проверка) | Месяцы до зрелости | 0 |
| Зависимость | Молодой MIT-проект, bus factor 1; форк посилен | Только CM6 (эталонно зрелый) | Obsidian |
| «Текст остаётся текстом» | Да (CM6) | Да | Да |
| Mobile | CM6-типичный; проверить руками | Тот же + своя доводка | Obsidian mobile |
| Риск главный | Смерть апстрима → форк | Хвост edge-cases съедает квартал | Цель не достигнута |

**Lean автора — A**: единственная ветка экосистемы с нужным поведением — CM6, а в ней готовое молодое дешевле зрелого своего; риск апстрима ограничен MIT-форком поверх стабильного фундамента, и B остаётся открытой дверью (те же CM6-плагины, наработки переносимы). Предусловие принятия — проверка Atomic Editor на телефоне до старта интеграции; провал проверки → B с ядром из codemirror-live-markdown.

Не рассматривалось: WYSIWYG (Milkdown/MDXEditor — reveal архитектурно недоступен, round-trip нормализует текст); HyperMD/ink-mde (мертвы); DQL-совместимость и Lua-runtime (research); MarkdownDB (решает несуществующую у нас проблему).
