# Discovery: прослойка CLI (D-6)

- Дата: 2026-08-21 · Масштаб: light (по observe: решения продиктованы docs/06 §1 и ADR-0006/0007/0008) · Вход: O-5/GF-1.3
- Прослойка = модуль раннера между супервизором и процессом `claude` в контейнере задачи: запуск, флаги, парсинг stream-json, завершение.

## Что уже решено (не переоткрываем)

- Процесс живёт всю задачу, указания — в stdin живого процесса; stop = SIGTERM; контрактные тесты S3/S4/S5 + пин версии CLI — обновление решением (ADR-0007).
- Контейнер-на-задачу, комплект `~/.claude` от брокера, `CLAUDE_CONFIG_DIR` per-задача (ADR-0006, заимствование yao).
- Вехи из stream-json (границы ходов со смещениями, tool-вызовы), сырьё файлом, парсер пишет инкрементально (ADR-0005/0008).

## Заимствования yao (docs/06 §1, принимаются как данность light-цикла)

Heredoc-запуск, системный промпт файлом (`set -e`); базовые флаги stream-json (`--input-format/--output-format stream-json --include-partial-messages --verbose`); `--session-id` (первый запуск) / `--resume` (после рестарта); метка «continuation» ставится сразу после старта процесса (файл сессии создаётся при старте — даже упавший стрим означает «дальше только resume»); stderr — информация, не сигнал отмены; невалидный JSON — continue; дренаж строк сверх лимита (50 МБ); exit 0 без `result` при непустом stderr = «setup failed» (ловушка S1b); SIGKILL после финального `result` (зависание stream-json-режима; в контейнере-на-задачу детей беречь не нужно — контейнер умирает с задачей); `parent_tool_use_id` → дерево саб-агентов; правило «MEMORY.md не перезаписывать». Не берём: игнорирование `thinking_delta` (регресс наблюдаемости), белый список из трёх флагов, suspend/resume групп.

## Остаётся решить

1. Схема идентификатора сессии CLI (единственная настоящая развилка — Q1).
2. Видимость reasoning в панели (Q2).
3. Значения настроек (лимит строки, heartbeat парсера) — константы GF-2, не архитектура.

## Open questions (владельцу)

- **Q1. Идентификатор сессии:** (а) `--session-id` = UUIDv7 из строки sessions (создаётся транзакцией до старта процесса) — одна система идентификаторов ADR-0005, истина в БД; (б) UUIDv5-функция от (задача, поколение) как у yao — сессия восстановима без чтения БД, но вторая схема ID и неочевидные коллизии при ретраях. Рекомендация — (а): у yao не было своей таблицы сессий, у нас есть.
- **Q2. Reasoning (thinking) в панели:** (а) виден только в drill-down сырья (приходит бесплатно из ADR-0008, вехи не трогаем); (б) дополнительно краткая веха «мысль» на блок reasoning — «о чём думает агент» из журнала 90 дней, но это текст модели в БД, против позы «без содержимого» в вехах. Рекомендация — (а).
