# Design: стек Гефеста (D-1) — альтернативы (light)

- Дата: 2026-08-20 · Входы: discovery (2 раунда, C-С1 — биллинг по ресурсам), research (Rust-экосистема/Bun)

## Проблема и силы

Язык бэкенда (раннер + панель) и фронтенд-набор. Силы: C-С1 — idle-RAM/CPU = деньги ежемесячно; F7 — один оператор, но Rust/TS/Python — родные языки владельца; код пишут Claude-агенты; «быстро переехать»; надёжность супервизора (переподхват, идемпотентность); прослойка CLI и MCP-recall — нужен зрелый MCP-SDK.

## Альтернатива A — Rust: axum + tokio + sqlx (+rmcp, +pgvector-crate); фронтенд React 19 + Vite 8 + TanStack Router/Query + Tailwind 4; Bun как toolchain

- **Силам:** C-С1 — лучший idle-RAM из всех (~5–30 МБ RSS класс); супервизор — tokio::process, строгая типизация, один бинарь (+статика фронта внутри — ноль лишних процессов); MCP — официальный rmcp 3.x (зрелый); pgvector — официальный крейт; родной язык владельца; агенты пишут Rust уверенно.
- **Легче:** деплой (один бинарь + Postgres в compose), эксплуатация, ресурсы. **Тяжелее:** скорость итерации (компиляция, строгость в прототипной фазе) — минус к «быстро»; sqlx 0.9 свежий (проверить совместимость pgvector, фолбэк 0.8).
- **Усилия:** паритетные 4–7 недель остаются, с риском +10–20% на итерационный налог Rust.
- **Ломается:** если понадобится очень быстрое прототипирование UI-серверной логики — компенсируется тем, что вся «быстрая» часть живёт во фронте (TS).

## Альтернатива B — Go: chi/echo + database/sql (+pgx); тот же фронтенд

- **Силам:** C-С1 — хорошо (в 2–4 раза тяжелее Rust по RAM, всё ещё в разы легче Python); итерация быстрее Rust (компиляция мгновенная, язык проще); супервизор — горутины, зрело. **Но:** Go — не родной язык владельца (в отличие от Rust!); MCP-SDK на Go — не официальный первого класса (не проверялся research-ом); «современность» по ощущению владельца ниже.
- **Легче:** скорость итерации. **Тяжелее:** язык вне родной тройки владельца — bus-factor хуже, чем у A; RAM дороже A при C-С1.
- **Ломается:** нигде драматически — честный середняк, проигрывающий A по двум персональным силам (родной язык, C-С1-экономика).

## Матрица

| Сила | A: Rust | B: Go |
|---|---|---|
| C-С1 idle-ресурсы | **good** | fair |
| Родной язык владельца | **good** | poor |
| Скорость итерации | fair | good |
| MCP/pgvector зрелость | **good** (rmcp 3.x, официальные крейты) | не подтверждена |
| Супервизор | good | good |

**Не рассматривали:** Python/Starlette (статус-кво по наследству) — C-С1 делает его худшим по прямым деньгам (60–150+ МБ на воркер), единственное преимущество «скорость» съедается тем, что пишут агенты; Bun/Node как прод-бэкенд — лишний резидентный рантайм против C-С1; Leptos/htmx — отказ от React против ответа №3 владельца.

## Фронтенд (общий для A и B)

React 19 + TypeScript + Vite 8 (Rolldown) + TanStack Router + TanStack Query + Tailwind CSS 4; SSE — нативный EventSource + инвалидация Query. **Bun — как toolchain** (bun install / bun test / dev-скрипты; забавный факт: Bun принадлежит Anthropic и питает Claude Code), сборка — Vite 8, прод — статика из axum. Bun-как-бандлер — не сейчас (для React-SPA Vite зрелее); пересмотр — если Bun-бандлер догонит.

## Что нужно, чтобы решить

Ничего внешнего: обе силы, разводящие A и B (родной язык, C-С1), — уже отвечены владельцем. Рекомендация design: **A**.
