# Discovery: модель сессий и журнала (D-5)

- Дата: 2026-08-21 · Масштаб: light (standard по observe, понижен: ADR-0005/0007 закрыли носители, retention, приватность и события доставки) · Вход: O-5/GF-1.1
- Легенда: «сессия» — один живой процесс `claude -p`/`--resume` (u sameuuid CLI); «веха» — событие session_events в БД; «сырьё» — полный stream-json файлом (0700, вне бэкапа, janitor 30 дней — ADR-0005); «ход»/«шаг» — словарь docs/03 §3.

## Что уже решено (не переоткрываем)

- Носители и retention: вехи в БД 90 дней с контрактом саммари; сырьё файлами 30 дней; «удалить с производными» включает raw-файл; scope_class на sessions/session_events (ADR-0005).
- Запись: append-only поток `(stream_id, version)` + state-таблица одной транзакцией; инкрементально, не батчем; reconciliation осиротевших при старте (ADR-0005).
- События доставки — в `command_deliveries`, не в вехах; синтетическое закрытие `interrupted` при SIGTERM; вопрос агента — событие session_events; из api_retry-вех — белый список полей (ADR-0007).
- Жизненный цикл процесса: контейнер-на-задачу, сон `waiting_answer` без остановки в v1, `sleeping`/`stopping`/`sleeping_cold` за флагом (ADR-0006/0007).
- Одна задача — одна живая сессия (частичный UNIQUE); канал панели — NOTIFY + курсор + gap-detection (ADR-0005).

## Остаётся решить (ядро D-5)

1. Машина состояний сессии — консолидировать разбросанное по ADR-0006/0007 в одно перечисление с переходами (кто переводит, какое событие пишется).
2. Инвариант «видимое = залогировано» — что панель показывает в реальном времени и откуда.
3. Таксономия вех — какие stream-json-события становятся вехами (объём БД против наблюдаемости).
4. Контракт саммари — когда исполнитель суммаризирует и что происходит при невыполнении контракта.
5. Родословная сессий задачи — ретрай/рестарт порождает новую сессию; связь и отображение.

## Open questions (владельцу)

- **Q1. Live-вид панели:** строго «видимое = залогировано» — панель показывает только вехи из БД (задержка = запись вехи, секунды); или дополнительно live-хвост сырого потока (терминальный вид работы агента, помечен «сырьё, вне журнала», читается раннером из файла)? Второе — наблюдаемость «что он сейчас печатает» ценой канала panel←raw в обход БД.
- **Q2. Гранулярность вех:** (а) только границы ходов + именованные события (вопрос, interrupted, limit, доставка-маркеры) — минимум объёма; (б) + каждый tool-вызов (имя инструмента, длительность, статус — без аргументов) — «чем занят агент» видно из журнала 90 дней, но вех на порядок больше. Сырьё 30 дней есть в обоих вариантах.
- **Q3. Момент саммари:** исполнитель суммаризирует (а) при завершении/усыплении сессии — дешевле по токенам, между — панель живёт вехами; (б) на каждой границе хода — всегда свежее «что сделано», но токены на каждый ход (против экономики подписки).
