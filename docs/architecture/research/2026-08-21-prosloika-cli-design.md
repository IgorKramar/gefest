# Design: прослойка CLI (D-6)

- Дата: 2026-08-21 · Масштаб: light · Вход: discovery + ответы владельца (Q1-а, Q2-а)

## Общая часть (заимствования yao как данность — discovery)

Запуск heredoc-скриптом, системный промпт файлом (`set -e`); флаги stream-json всегда; парсер — явная стейт-машина с инкрементальной записью вех и сырья (ADR-0005/0008); stderr копится, не отменяет; невалидная строка — continue; дренаж строк > лимита (константа GF-2, старт 50 МБ); «exit 0 без `result` + непустой stderr» = setup failed → ретрай-путь ADR-0007; SIGKILL после финального `result`; `parent_tool_use_id` → дерево саб-агентов в вехах; heartbeat парсера (константа GF-2); MEMORY.md не перезаписывается комплектом брокера; `thinking_delta` парсится в сырьё (не игнорируется — регресс наблюдаемости yao не повторяем).

## Развилка Q1: идентификатор сессии CLI

| Критерий | A: UUIDv7 из sessions | B: UUIDv5-функция (yao) |
|---|---|---|
| Системы ID | Одна (ADR-0005) | Вторая схема + namespace-константа |
| Восстановление без БД | Нет (сценарий пуст: без БД раннер не работает) | Да |
| Ретраи/поколения | Новая строка = новый ID, родословная `parent_session_id` (ADR-0008) | Коллизия: та же функция → тот же ID, нужен счётчик поколений в ключе |
| Порядок создания | Строка sessions транзакцией **до** старта процесса; `--session-id` из неё; `--resume` после рестарта раннера | ID вычислим в любой момент |

**Выбрано владельцем — A.** Флаг continuation отдельного KV-стора не требует: он выводим из состояния строки sessions (были ли ходы) — истина уже в БД.

## Развилка Q2: reasoning в панели

A: thinking виден только в drill-down сырья (ADR-0008), вехи без содержимого. B: веха «мысль» на reasoning-блок — текст модели в БД, против позы вех. **Выбрано владельцем — A.**
