# Decision summary: канон памяти Гефеста (D-8)

- Дата: 2026-08-20
- Фаза: Decide (deep-цикл D-8)
- Входы: discovery (`2026-08-20-kanon-pamyati.md`, 2 раунда), research (`...-research.md`), design (`...-design.md`, альтернативы A/B/C/D)
- Легенда: `С7` — сценарий покрытия привычек Obsidian; `C-Н1/C-Н5` — ограничения (бюджет/один источник истины); `C-П1/C-П2` — ограничения этого цикла (мастер-агент-редактор / память ролей); `Р-1/Р-2` — предложения исполнителя, принятые владельцем; `F-П1…F-П6` — силы цикла; D-N — decision-map.
- Статус: **принято владельцем** («Я тоже за А + pgvector…» → редакция исполнителя «дверь сейчас, двигатель по замеру» → «Согласен», 2026-08-20). Ожидает roast + ADR.

## 1. Выбранная альтернатива

**A: канон знаний и памяти — в Postgres Гефеста**, рядом с оперативным каноном (D-2), **+ pgvector как спроектированная дверь с включением по замеру**.

1. **Хранение:** таблицы памяти в Postgres — записи со скоупами (глобальный / проект / роль), классами (правило, ловушка, learning, справочник, карточка, журнал), слоем recall (ядро/тело — Р-1), автором, ревизиями, русским FTS (`to_tsvector('russian')` — эксплуатационно доказан). Wiki-линки и бэклинки — таблица связей + резолвер (общие с С7-слоем документов).
2. **Recall — трёхслойный (Р-1):** ядро (правила+ловушки+процессные инструкции, бюджет ≤ 12 КБ, попадание — редакционное решение мастер-агента) и индекс-аннотации инжектятся в старт каждой сессии; тело — recall-by-need через MCP/CLI.
3. **Подъём (C-П1):** хук конца сессии собирает кандидатов из личных памятей/сессий → таблица кандидатов со статусами → **мастер-агент утверждает/правит/отклоняет**, след в журнале.
4. **Выгрузка вниз (C-П2, F-П6):** генератор кладёт производные файлы из канона — фрагменты CLAUDE.md-класса и memory-файлы **роли** в рабочие cwd (мост «роль → cwd»; правила yao-genfile: свои файлы помечены, `MEMORY.md` не перезаписывать). Локальные файлы — производные, не истина.
5. **pgvector — дверь, не двигатель:** расширение установлено; таблица `memory_embeddings (entry_id, model, dim, vector)` отдельная, размерность **не прибита** (урок EverOS `_DIM=1024`); backfill-команда предусмотрена. **Триггер включения — замер:** recall-запросы логируются; доля пустых/нерелевантных ответов FTS > 10% за неделю → включаем векторную ногу локальной мультиязычной моделью (класс e5-multilingual, CPU) + гибридный поиск. До триггера векторная нога не строится.
6. **Дневники (.remember) — Р-2 подтверждено:** входят в канон классом «журнал»; плагин остаётся локальным писателем, его артефакты поднимаются штатным подъёмом.
7. **EverOS — отклонён как зависимость** (три блокера research, в т.ч. подтверждённый исполнением jieba-блокер), принят как донор идей: entry-id, поэнтрийная переиндексация, durable-очередь, цикл recall→capture→flush, fail-loud конфиг фоновых LLM-процессов.
8. **Фоновая консолидация/дедуп:** opt-in задачи на бесплатном OpenRouter, конфиг по образцу ome.toml (каждая стратегия выключается строкой, опечатка ключа — ошибка старта); по умолчанию включён только дедуп-кандидат при подъёме.

## 2. Почему это решение

- **Один источник истины буквально (C-Н5):** память въезжает в ту же СУБД, что задачи/журнал (D-2 проектируется сейчас — F-П5); принцип «база — истина, файлы — выгрузка» распространён на память без второго механизма согласованности (каскад B отвергнут как «свой мини-EverOS»).
- **Русский поиск — доказан, не обещан** (F-П1, С7): FTS уже работает в agent-dashboard; альтернативы либо строят его же (B), либо ломаются на нём (C — подтверждено исполнением).
- **Ноль новых сервисов (F7):** тот же Postgres, тот же бэкап, та же панель.
- **pgvector по замеру, не авансом:** эмбеддинг-провайдера в бюджете C-Н1 сегодня нет (OpenRouter их не отдаёт); дверь спроектирована так, что включение — backfill, а не пересборка (техника «замер вместо согласия»).
- **Гибридный подъём с мастер-агентом (C-П1)** — баланс F-П2: автоматика не мусорит, ритуал не забывается, след остаётся.

## 3. Что мы отдаём (принятые минусы)

- Правка знаний — через панель/CLI Гефеста, не «открыл файл в Obsidian» (привычка редактора приносится в жертву единственности истины; смягчение — read-only экспорт в git по желанию, отдельной задачей).
- Git-истории знаний нет — ревизии живут в БД (бэкап и restore — те же, что у всего канона).
- Векторный recall не работает с первого дня — сознательно, до замера-триггера.
- Мост «роль → cwd» — наша механика, её баги — наши (готовых аналогов, кроме образца yao, нет).
- Миграция контента шести слоёв (35 статей, карточки, дневники 1,3 МБ, memory-файлы) — ручная скриптовая работа, дни.

## 4. Границы пересмотра

1. **Замер-триггер сработал** (FTS-промахи > 10%/нед) — включение векторной ноги: это предусмотренный путь, не пересмотр.
2. **Локальная embedding-модель не тянет русский** на нашем железе — пересмотр способа (платный API против правки бюджета C-Н1 — решение владельца).
3. **EverOS открывает апстрим + русский first-class** — пересмотр границы «донор идей» (проверяется квартальной ревизией GF-4).
4. **Канон превышает ~5–10 тыс. записей** и SQL-бэклинки/FTS деградируют — пересмотр индексного слоя (материализация графа, выделенный поиск).
5. **Мастер-агент-редактор становится бутылочным горлышком** подъёма (очередь кандидатов растёт неделями) — пересмотр редакционной модели.

## 5. Операционные последствия

- Схема памяти проектируется **вместе с D-2** (это следующий цикл; вход от D-8: скоупы, слои, кандидаты, связи, embeddings-дверь).
- SessionStart-хуки переключаются с vault-инжекции на выгрузки канона (ядро+индекс) — vault-хук доживает до миграции контента.
- Логирование recall-запросов и их результатов — с первого дня (иначе триггер п.4.1 неизмерим).
- Бюджет ядра (≤ 12 КБ) — автоматическая проверка (тест/триггер), не дисциплина.
- Миграция: 30-resources (35 статей) → класс «правила/ловушки/приёмы»; карточки людей → «карточка»; дневники .remember → «журнал»; живые memory-файлы ролей — первичные кандидаты подъёма.
- Фоновые LLM-задачи — только бесплатный OpenRouter, конфиг fail-loud, всё выключаемо.

## 6. План (вливается в фазы Гефеста)

1. D-8-ADR принят → вход в **D-2 (схема данных)** — память как полноправная часть схемы.
2. Ф1: таблицы памяти + FTS + MCP/CLI recall + логирование запросов.
3. Ф1–Ф2: генератор выгрузки вниз (ядро/индекс/память ролей), подъём-конвейер с мастер-агентом.
4. Ф2: миграция контента шести слоёв; переключение хуков; **vault выводится** (после проверенного restore — DoD Ф3 ADR-0001).
5. По триггеру: pgvector backfill + гибридный поиск.

## 7. Критерий выполненности

- ADR-0003 принят; вход для D-2 зафиксирован.
- Агент любой роли на любом cwd получает при старте ядро+индекс из канона (не из vault) и достаёт тело по запросу через MCP/CLI.
- Роль помнит своё между worktree и машинами (memory-файлы роли генерируются из канона).
- Learning, предложенный агентом в конце сессии, проходит путь кандидат → решение мастер-агента → канон → виден всем в следующих стартах; след решения в журнале.
- Дневник дня доступен поиском из панели; vault-копия базы знаний выведена.
- Лог recall-запросов накапливается; отчёт «доля промахов FTS» доступен в панели.
