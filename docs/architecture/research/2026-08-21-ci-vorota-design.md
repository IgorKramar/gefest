# Design: CI и ворота на мерж (D-12)

- Дата: 2026-08-21 · Масштаб: light · Вход: discovery + ответы владельца (Q1-а, Q2-а)

## Конструкция

**GitHub Actions**, один workflow с job-ами по путям (paths-filter — доки не гоняют Rust-сборку):

- `rust`: `cargo fmt --check` → `cargo clippy -- -D warnings` → `cargo test` (юнит + контрактные против фальшивого исполнителя, ADR-0009) → `cargo sqlx prepare --check` (offline-метаданные закоммичены).
- `migrations`: Postgres service-контейнер → `sqlx migrate run` на чистой БД → смоук + отрицательные тесты RLS (ADR-0005: NULL-контекст обязателен).
- `front`: Bun: install → `tsc --noEmit` → `vite build`.
- Кэш cargo/bun; таргет — «зелёный за ≤ 5 мин».

**Ворота (Q1-а):** main защищён — PR + зелёный CI + актуальность ветки; исключение — владелец: прямой пуш для `docs/**`, `*.md` и hotfix (право, не привычка). Агенты — только PR (scoped-токены пула без права пуша в main — усиливает ворота токеном, не только правилом).

**Деплой (Q2-а):** CD — дверь. v1: скрипт `deploy.sh` на РФ-VM (`git pull && docker compose up -d --build`), вызов владельцем через tailnet (ssh с ноутбука/телефона); триггер пересмотра — деплой чаще N раз/нед или второй оператор → self-hosted runner решением.

## Развилки (закрыты ответами)

| | Выбрано (а) | Отклонено (б) |
|---|---|---|
| Q1 | PR-ворота для кода; доки владельца — напрямую | Всё через PR: док-коммиты ждут CI без выгоды |
| Q2 | Ручной деплой скриптом, CD — дверь | Self-hosted runner: резидентный сервис (C-С1) + CI-код рядом с продом |

Не рассматривалось: сторонние CI (репо уже на GitHub, private-минут Free хватает); прогон контрактных тестов против живого CLI в CI (жжёт окно подписки — только вручную при обновлении CLI, ADR-0009).
