# Decision summary: взаимодействие агентов и чат (D-9)

- Дата: 2026-08-21 · Фаза: Decide (standard) · Входы: discovery (Q1–Q7), design (A/B/C; research пропущен обоснованно)
- Статус: **принято владельцем** («А», 2026-08-21).

## Выбранное

**A: чат — append-only поток + курсоры; mailbox — единый инбокс** + общая часть design:

1. **Чат:** один общий канал (комнаты — дверь: `channel_id` в схеме, активен один); `chat_messages (channel_id, version)` — поток по конституции ADR-0005; чтение — pull MCP-инструментом на границах хода; `read` = продвижение курсора агента; история доступна новым участникам с нуля; gap-detection штатный.
2. **Mailbox:** адресный `message` — единый инбокс ADR-0007 (push в stdin, `queued` до пробуждения, delivered каузальный); отметка `read` — при чтении инбокса агентом; «доставлено ≠ прочитано» видно в панели.
3. **Права:** адресовать и писать в чат — в рамках общего проекта; broadcast-указания — только владелец; владелец видит всё; след — автор/адресат по построению.
4. **Эскалация:** message не прочитан дольше порога (настройка, старт 24 ч) → алерт (факт+ссылка) с действиями «запустить роль / переадресовать / снять».
5. **Передача работы:** своему сабагенту — автоматически (внутри контейнера, механика Claude Code, Гефест не участвует); другому агенту — предложение `pending` → подтверждение владельца; автопередача доверенным парам — дверь D-16.
6. **Владелец в чате:** message с пометкой owner, pull отдаёт с приоритетной маркировкой + инструкция ролей «сообщения владельца — первыми»; гарантия и немедленность — кнопкой «отправить как указание».
7. **Приватность:** таблицы чата/mailbox — scope_class; retention тела 90 дней (политика ADR-0007 п.8); «удалить с производными» включает; алерты — факт+ссылка.

## Почему

Поток с курсорами — уже конституция схемы (третье применение после task_events/session_events): чат не добавляет механизма; fan-out платил бы ×N записей и терял историю — координационную ценность канала; push чата в stdin шумел бы в контексте каждого (отклонено владельцем Q2).

## Что отдаём

Чат не гарантирует своевременность (агент читает на границе хода — сообщение «стоп» через чат может опоздать; лечится указанием); read-курсор чата не различает «прочитал и понял» / «пролистал» — дисциплина модели вне гарантий; эскалационный порог один на всех в v1 (per-роль — настройкой позже).

## Операционные последствия

GF-5/волна 2: `chat_messages`, курсоры читателей, `read` у инбокса, `channel_id`-дверь — forward-миграцией. GF-2+: MCP-инструменты чтения/письма (границы — D-16), эскалационный таймер, панель чата с «непрочитанным» и «отправить как указание». Инструкция ролей — приоритет сообщений владельца.

## Границы пересмотра

Один канал становится шумным (агенты жалуются/пропускают) → включение комнат per-project (дверь готова); частые опоздания чат-«стопов» → пересмотр Q2 для класса срочных; второй оператор → ревизия прав broadcast; автопередача доверенным парам — по практике предложений (D-16).
