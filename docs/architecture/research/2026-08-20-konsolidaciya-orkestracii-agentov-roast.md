# Roast: decision «консолидация оркестрации агентов»

- Дата: 2026-08-20
- Цель: `2026-08-20-konsolidaciya-orkestracii-agentov-decision.md`
- Роли: devil-advocate (A-1…A-8), pragmatist (P-1…P-7), junior-engineer (J-1…J-9), compliance-officer (C-1…C-7), futurist (F-1…F-9). Полные отчёты — в журнале сессии; здесь — агрегат и вердикт.
- Дополнительно: проверка первоисточника (Consumer Terms Anthropic) выполнена оркестратором после находки C-1.

## Схождения независимых линз (сигнал)

### Кластер 1 — ToS: пилот A в текущем виде — осознанное нарушение, а не серая зона
**C-1 (high) + F-7 (high) + проверка первоисточника.** Consumer Terms: креды аккаунта нельзя делать доступными кому-либо (§2); автоматизированный доступ — только через API-ключ или где явно разрешено (§3). Headless `claude -p` — официальная документированная функция Claude Code → путь B аргументируем как использование самого продукта. Путь A — монтирование кредов подписки в песочницу стороннего продукта (yao) — под запретом по букве; вторичные источники сообщают о явном запрете подписочного OAuth в сторонних продуктах с 02.2026. Цена реализации риска — бан аккаунта Max 20x = остановка всех исполнителей.
**Следствие, которого нет в decision:** без подписки путь A требует либо API-токенов (нарушает C-Н1), либо не-Claude исполнителей через A2O (нарушает ответ №1). То есть **SS-1 фактически предрешён не техникой, а условиями использования** — пилот проверяет то, чем нельзя пользоваться.

### Кластер 2 — пилот слеп и нечестен по построению
**A-5 (high) + P-5 + A-1 (high) + A-3 (high) + P-1 + J-3/J-4/J-5.** Три источника истины на неделю, детекторы не видят yao (повтор AD-7 внутри инструмента его проверки); «впритык» судит пилотирующий с заявленной симпатией; критерий обходится двумя маленькими задачами и не проверяет С4 (параллельность); неделя при 1–2 ч/день = 7–10 часов на пять SS — вердикты «не успел» неизбежны; SS-1/SS-3 непроверяемы по написанному (термины не определены, процедур нет).

### Кластер 3 — Ф0 недооценена, отказы раннера не спроектированы
**A-6 (high) + P-4 + P-2 (high) + F-2 (high).** Раннер-владелец процессов: рестарт гасит cgroup — все сессии; переподхват не описан; идемпотентность доставки (упал между spawn и `delivered` → двойной spawn) не оговорена; креды — единая точка молчаливого отказа (код 0 + DEVNULL — дважды молчаливая мода); интерфейс CLI (флаги, форматы файлов) — не контракт и сменится: нужна своя прослойка. Реальный объём Ф0 — 8–12 дней, не «немедленно».

### Кластер 4 — эксплуатация без страховочных тросов
**P-3 (high) + P-7 (high) + C-2 (high).** Вывод vault убивает единственный git-бэкап знаний — в DoD нет проверенного restore; ни одного канала уведомлений (heartbeat ~1 час работы); git-токены (прямой ущерб третьим лицам при утечке) не упомянуты в решении вовсе — нужна матрица секретов.

### Кластер 5 — периметр и чужой код
**C-3 (high) + C-4 (high) + C-5.** «VPN/proxy + auth» — одна скобка для решения, меняющего класс риска; принцип «панель не смотрит в публичный интернет» надо зафиксировать в ADR. Пилот заводит рабочий код в платформу с непрочитанным сетевым поведением («логика верификации» лицензии — что она шлёт?) — пилот только на некоммерческом репо + egress-аудит. Supabase (eu-west-1, карточки людей, контекст клиентов) — вывод с дедлайном, не «когда-нибудь».

### Кластер 6 — документ не самодостаточен
**J-1…J-9.** Легенда кодов отсутствует; латиница/кириллица смешаны в «C1–C7» (grep теряет употребления); A/B/C/D, раннер, детекторы, AD-19+, yao/DSH/EverOS — без представления; Ф3 «канон памяти» нечитаем даже с контекстом (честно пометить как отложенное до Document).

### Кластер 7 — дрейф на горизонте (futurist, принять сейчас — дёшево)
**F-1 (high):** триггеры §4 пассивны — нужна квартальная календарная ревизия задачей в панели + чек-лист паритета. **F-3:** при исходе A — обратный экспорт из yao с первого дня как условие эксплуатации. **F-5:** при исходе B — поле автор/адресат в схеме сразу. **F-6:** каждому «решается при Document» — дедлайн и умолчание. **F-9:** зафиксировать границу «тонкого» B — список того, что B не строит никогда.

## Что выдержало обстрел (все роли согласны)

Конструкция «ворота + default-to-B + тайм-бокс», асимметрия обратимости как рамка, Ф0 как инвариант обоих миров, «done = состояние внешнего мира» + детекторы (самая переносимая ценность контура), resolucija П-1 (compose), ловушка S1b, зафиксированная до продакшена.

## Вердикт агрегатора

Решение конструктивно здраво, но **Кластер 1 меняет его суть**: пилот A в задуманном виде — не проверка гипотезы, а осознанное нарушение условий использования с аккаунтом всей команды на кону, и его «успех» не сделает нарушение приемлемым. Остальные кластеры чинятся правками decision и плана (список выше). Владельцу предстоит выбор:

- **(а) Исход B напрямую** — пилот A отменяется по C-1 (SS-1 предрешён условиями, не техникой); yao и DSH остаются донорами идей; триггер пересмотра: Anthropic легализует подписочное использование в сторонних продуктах / yao получает одобрение / появляется бюджет на API-токены. Применить кластеры 3–7 к плану B. ← рекомендация агрегатора.
- **(б) Пилот с осознанным принятием ToS-риска** — зафиксировать письменно, что владелец принимает риск бана аккаунта Max; применить кластеры 2–7 (пилот на некоммерческом репо, egress-аудит, регистрация задач в базе, процедуры SS). Агрегатор не рекомендует: цена реализации — остановка команды.
- **(в) Запрос в Anthropic** (sales/support) с описанием кейса до пилота — честный путь легализации A; цена — неопределённая задержка; на время ожидания действовать по (а), Ф0 не ждёт ничего.
