# Decision summary: документный слой (D-10)

- Дата: 2026-08-21 · Фаза: Decide (standard) · Входы: discovery (Q1–Q6), research digest, design (A/B/C)
- Статус: **принято владельцем** («А с встроенным планом Б, плюс YAML frontmatter», 2026-08-21).

## Выбранное

**A: CodeMirror 6 через Atomic Editor + фазировка** + общая часть design + дополнение владельца:

1. **Редактор:** `@atomic-editor/editor` (CM6): reveal сырого markdown у курсора, [[автодополнение]], подсветка кода, read-only для чтения с телефона. **Предусловие интеграции:** ручная проверка на телефоне и React 19 Strict Mode; провал → план Б. **План Б встроен:** форк MIT-кода поверх стабильного CM6; референсы — codemirror-live-markdown, Joplin Rich Markdown.
2. **YAML frontmatter (дополнение владельца):** блок `---` в начале документа — источник метаданных; при сохранении парсится и синхронизируется в колонки/таблицы БД (теги, даты, произвольные свойства — jsonb), как линки в `links`; в редакторе рендерится свёрнутой панелью свойств (Obsidian-паттерн Properties), сырой YAML — по клику; конфликт «frontmatter против БД» невозможен по построению — БД всегда производная от текста.
3. **Хранение:** markdown в Postgres; история правок — поток событий (восстановление версий); CAS; scope_class/RLS.
4. **Линки:** [[wiki-линки]] → таблица `links` при сохранении (битая/живая помечена); бэклинки и будущий граф — запросы по ней; русский FTS — хранимый tsvector.
5. **Виды (dataview-класс):** DQL не тащим; `saved_views` — JSON-спека (фильтры тег/дата/линки/frontmatter-свойства, сортировка, колонки, layout) → параметризованный построитель SQL; встраивание fenced-блоком ` ```view `; computed-поля в спеку не входят (граница DSL); аварийный люк — сохранённые raw-SQL под read-only ролью, только владельцу.
6. **Записи агентов:** рабочие документы задачи — свободно; канон — предложение → подтверждение (pending, четвёртое применение).
7. **Периодические заметки:** daily/weekly/monthly по шаблонам, автосоздание при открытии; шаблоны — документы-заготовки. **Кнопка «в память»:** выделение → кандидат карточки канона (ADR-0003). **Импорт vault:** выборочный, битые линки помечаются.
8. **Фазировка:** v1 — линки/бэклинки, FTS, frontmatter, периодические заметки, теги, шаблоны, подсветка, история, «в память», импорт, виды-JSON без GUI. Итерация 2 — граф связей, GUI-конструктор видов (Bases-паттерн), raw-SQL-люк.

## Почему

Нужное поведение редактора существует только в CM6-ветке (research: Obsidian, SilverBullet, Joplin — все там); готовое молодое + MIT-форк-план дешевле зрелого своего на месяцы; DQL мёртв как переносимая цель — сам Obsidian ушёл к сохранённым видам, а наши метаданные уже в Postgres; frontmatter-как-источник сохраняет «текст остаётся текстом» и переносимость документов (экспорт = файлы без потерь).

## Что отдаём

Bus factor апстрима ≈ 1 (принято: пин версии + форк-готовность); мобильная правка — CM6-шероховатости (чтение — без проблем); произвольные frontmatter-свойства в jsonb — без схемной валидации в v1; граф и GUI-видов ждут итерации 2.

## Операционные последствия

GF-5/волна 2: documents, document_events, links, tags, saved_views, frontmatter-jsonb — forward-миграцией. Новая задача GF-7 (документный слой) — после GF-2-ядра; проверка Atomic на телефоне — до начала GF-7. Вывод vault — после паритета v1 + проверенного restore (предусловие ARCHITECTURE.md).

## Границы пересмотра

Провал проверки Atomic (телефон/React 19) → план Б (своя сборка, ядро из codemirror-live-markdown); смерть апстрима → форк; потребность в computed-полях → raw-SQL-люк, не расширение спеки (при системности — пересмотр решения о видах); мобильная правка болит на практике → отдельный упрощённый мобильный редактор (textarea+превью) как режим.
