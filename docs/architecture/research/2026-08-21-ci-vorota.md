# Discovery: CI и ворота на мерж (D-12)

- Дата: 2026-08-21 · Масштаб: light · Вход: O-12; правило «до первого кода GF-2» (decision-map)
- Репозиторий — приватный на GitHub (IgorKramar/gefest); будущие коммиттеры — владелец и агенты Гефеста (scoped-токены из пула, ADR-0010).

## Что уже задано

- Стек проверок предопределён ADR-0004/0009: Rust (fmt, clippy, test, sqlx offline-check), фронт (Bun: tsc, build), миграции против реального Postgres (service-контейнер), **контрактные тесты прослойки CLI против фальшивого исполнителя** (ADR-0009 — в CI; против живого CLI — только при решении об обновлении, вручную).
- Авторство — Igor Kramar, без упоминаний ИИ (конституция) — коммиты агентов проходят те же ворота.
- «Готово = мерж + зелёная проверка» — правило доски задач с первого дня.

## Остаётся решить

1. Режим веток: что защищено и для кого (код/докс, владелец/агенты).
2. Деплой (CD) из CI — сейчас или дверь (runner GitHub вне tailnet — доступ к РФ-VM нетривиален).
3. Платформа — GitHub Actions (репо уже там, private-минуты Free-плана достаточно для одного проекта) — рекомендация, не вопрос.

## Open questions (владельцу)

- **Q1. Ворота:** (а) main защищён для кода: только PR с зелёным CI (агенты — всегда PR; ты — вправе прямой пуш доков/hotfix); (б) всё через PR, включая доки и тебя — строже, но каждый док-коммит ждёт CI. Рекомендация — (а): сегодняшний темп докс-коммитов под PR не выиграет ничего.
- **Q2. Деплой:** (а) CD — дверь: в v1 деплой ручной (`git pull` + `docker compose up -d --build` на РФ-VM скриптом, вызов — с ноутбука/телефона через tailnet), автодеплой — при появлении причины; (б) сразу CD: self-hosted runner в tailnet на РФ-VM тянет по мержу. Рекомендация — (а): self-hosted runner — ещё один резидентный сервис (C-С1) и поверхность доверия (runner исполняет чужой CI-код рядом с продом).
