# Research digest: модель доставки (D-4)

Дата: 2026-08-20. Источники: (1) спайки S3/S4 исполнением; (2) агент-гид по документации Claude Code; (3) доноры (DSH inbox docs/03, yao docs/06 §4, AD research D-2).

## Question

Механика доставки указаний в живые headless-сессии: границы, остановка, лимиты, подтверждения.

## Headline finding

Вся необходимая механика существует штатно: **stdin живой сессии принимает сообщения в любой момент** — между ходами (S3: новый ход) и во время активного хода (S4: очередь, доставка на границе шага, поток цел). **SIGTERM — документированная остановка** (обрывает ход, гасит дерево Bash-процессов, SessionEnd-хуки, exit 143, сессия сохраняется для `--resume`). Лимиты наблюдаемы событиями `system/api_retry` (категории `rate_limit`/`billing_error`); interrupt-capability заявлена в `system/init` (interrupt_receipt_v1), но stdin-control-сообщение не документировано — прерывание только сигналом.

## Detailed findings

1. **S3 (исполнено)**: `--input-format stream-json` держит stdin; второе сообщение через 20 с — тот же процесс, та же сессия, новый ход со своим `result`. Закрытие stdin — чистое завершение.
2. **S4 (исполнено)**: сообщение, записанное во время 12-секундного tool-вызова, поставлено в очередь и обработано на границе шага (ответ на оба, `turns: 2`, один result после завершения). Инжектированное user-сообщение **не эхоится** отдельным событием вывода — подтверждение доставки наблюдается по эффекту (продолжение потока), не по эху.
3. **Остановка (документировано)**: SIGTERM → abort хода + terminate process tree Bash + SessionEnd hooks + exit 143; сессия непрерывно пишется в транскрипт → `--resume` работает. SIGINT в headless не документирован. Частичного result при обрыве может не быть — раннер закрывает ход синтетически (паттерн ремонта DSH-persistence).
4. **Лимиты (частично документировано)**: `system/api_retry` с `error_status`/категорией; авто-ретраи CLI до 10 с backoff; точный вид subscription-limit в stream-json не документирован — ловить обе категории + таймаут потока; `~/.claude/rate-limits.json` — неофициальный (панель уже использует; в прослойке CLI — как best-effort источник `resets_at` с fallback «нет данных»).
5. **Interrupt через stdin**: не документирован; TS-SDK `interrupt()` — абстракция SDK. Наш `stop` = SIGTERM (совпадает с решением C-Д1а: перебив = только stop).
6. **Доноры**: словарь DSH (followup/steer/inject, claim на границе) ложится на факты S3/S4 дословно; yao-анти-урок (best-effort с дропом) исключается тем, что истина — таблицы ADR-0005, а stdin — транспорт.

### Спайк S5 (2026-08-20, после roast-запроса devil-advocate)

Три сообщения (стартовое + два инжектированных на 4-й и 6-й секунде 10-секундного tool-вызова): **все доставлены, порядок FIFO сохранён** (ответ «РАЗ / ДВА / ТРИ» по порядку); CLI **склеил очередь в одно продолжение** после tool_result; `result.num_turns = 2` при трёх user-сообщениях — **счётчик ходов не годится как каузальный маркер per-сообщение**. Годный маркер: активность потока, начавшаяся после `tool_result` инструмента, который был in-flight на момент записи (для idle-записи — начало новой активности вообще).

## Caveats and unknowns

Вид limit-ошибки в stream-json — проверить на живом исчерпании (первый инцидент задокументирует себя: прослойка CLI пишет сырые error-события в вехи); поведение очереди stdin при >1 ожидающего сообщения — предположительно FIFO (S4 с одним), проверка в GF-2-тестах; формат rate-limits.json нестабилен — только как подсказка.

## Implications for the design phase

Транспорт один — stdin + SIGTERM; истина — таблицы; развилка design сужается до **модели подтверждения** (чем является `delivered`) и **модели инициативы** (push раннером против pull исполнителем через MCP).
