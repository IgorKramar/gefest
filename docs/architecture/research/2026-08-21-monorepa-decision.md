# Decision summary: организация монорепы (D-17)

- Дата: 2026-08-21, ред. 2 — 2026-08-21 (закрытие находок roast) · Фаза: Decide (deep) · Входы: [discovery, 2 раунда](2026-08-21-monorepa.md), [research, 6 тем](2026-08-21-monorepa-research.md), [design A/B/C/D](2026-08-21-monorepa-design.md)
- Легенда: «крейт» — единица компиляции cargo; «раннер задач» — командный раннер сборки (не раннер-супервизор Гефеста); «сторож» — CI-проверка, падающая при рассинхроне артефактов; «дверь» — намеренно открытая точка расширения без обязательства реализовать; «перечисления-истина» — Rust-enum как единственный источник истины для статусов/видов (lookup-таблицы — зеркало миграциями, ADR-0005).
- Статус: **принято владельцем** («Так-то я за А», 2026-08-21); три уточнения по итогам roast подтверждены владельцем («Да», 2026-08-21): CC-4 (образ из GHCR), CC-1-интерим (SQL меняет владелец), CC-3 (флаг `embed-static`). Ред. 2 закрывает 37 находок roast; ADR-0014 — оформление.

## 1. Выбранная альтернатива

**A: доменная шестёрка крейтов** + общая часть design, с правками roast:

1. **Раскладка:** `crates/{core,db,runner,api,hef,fake-executor}` + `web/` + `infra/` + `tests/contract/` + `docs/`. Граф (→ = зависит от): `hef`→`api`→`runner`→`db`→`core`; `fake-executor`→`core`. Канонический ответ «куда класть код» живёт в одном файле (ARCHITECTURE.md, раздел «Структура»), остальные инструкции ссылаются (F-6).
2. **Границы крейтов:** `core` — типы/перечисления-истина/ошибки; без tokio/axum; `sqlx` — **optional feature** (default пуст), включает только `db` (CC-6) — derive `sqlx::Type` живёт под фичей, дефолтный граф чист; CI-сторож чистоты: `cargo tree -p core` без фич не содержит tokio/axum/sqlx (F-2); чистые переходы машин состояний в `core` разрешены явно. `api` — **модулен по доменам с первого дня** (documents/chat/mcp/views); модуль, переставший помещаться в голове, — кандидат в седьмой крейт (F-1). Все query-макросы — в `db`; migrations/ — внутри `db`.
3. **Workspace-база:** `edition = "2024"`, `workspace.dependencies`, `workspace.lints` в корне. Ловушка edition 2024: крейт не может сузить `default-features` относительно workspace-декларации — поэтому `default-features = false` в корне минимум для sqlx и tokio. Фичи sqlx фиксируются первым PR: `runtime-tokio`, `tls-rustls`, `postgres`, `uuid`, `time`, `migrate`, `json`.
4. **sqlx:** `.sqlx` в корне, `cargo sqlx prepare --workspace`; CI: сборка с `SQLX_OFFLINE=true` (env CI, не `.env` — sqlx#3836: флаг в `.env` ломает сам prepare); job с Postgres-service: `migrate run` → `prepare --check --workspace`; sqlx-cli пинован `--locked`, **единый источник версии — `mise.toml`** (оттуда же CI, H-5). **Цикл агента (CC-1):** комплект брокера ADR-0006 для задач над репо Гефеста несёт dev-БД клоном шаблона со схемой Гефеста; `mise sqlx-prepare` берёт DSN из комплекта. **Интерим до готовности брокера: SQL-запросы меняет только владелец** (подтверждено); runbook красного `prepare --check` — в README крейта `db`.
5. **Статика:** `bun run build` → `web/dist` → embed в `api` (**static-serve**; hashed — `immutable`, `index.html` — `no-cache`); отсутствие/пустота `dist` валит сборку проверкой в `build.rs` крейта `api` (поведение static-serve на пустом каталоге уточнить при внедрении — J-1); **feature-флаг `embed-static`** (CC-3, подтверждено): в dev/test/rust-job выключен — `api` собирается без dist и без bun-налога (H-2); включён в docker-job и релизе; полная сборка с embed — в merge-queue/nightly (закрывает «зелёный CI — красный деплой», B-7). Порядок bun→cargo — зависимостью mise-задач, не параллелью.
6. **`hef`** — тонкий бинарь (main + clap: `serve`, `migrate`, …); дверь `hef remote …` с границей: **remote-подкоманды не тянут server-фичи** (feature-gate или крейт `hef-client`, реэкспорт в тот же бинарь — F-4).
7. **Раннер задач — mise tasks** (Q8): параллельный dev (`vite dev` с прокси `/api` на бинарь + bacon), наследование тулчейна (включая **пин Rust в `mise.toml`**), тот же раннер в CI; justfile не заводится.
8. **Docker и деплой (CC-4, подтверждено):** `infra/Dockerfile` (bun → cargo-chef → slim), контекст от корня; **прод-образ собирает CI и пушит в приватный GHCR; `deploy.sh` = `docker compose pull && up -d`** — линковка не конкурирует с живыми сессиями на VM (B-8); уточняет способ получения образа при ручном деплое ADR-0012. `.dockerignore`: `target/`, `web/node_modules`, `web/dist`, **`.git/`, `.env*`, `reference/`, `docs/`, ключевые маски** (C-1); секреты сборки — только `--mount=type=secret`. Образ исполнителя — `infra/executor-image/`, собирается **без кредов и секретных ARG** (аутентификация — только инжекцией раннера, ADR-0006), хранение — тот же приватный GHCR (C-6).
9. **CI-фильтры (CC-2):** rust-job — `crates/**` **+ корневые `Cargo.toml`/`Cargo.lock` + `.sqlx/**`** (B-2); front-job — `web/**`; migrations-job — `crates/db/migrations/**`; contract-job — `tests/contract/**` + `crates/runner/**` + **`crates/fake-executor/**` + `crates/core/**` + `infra/executor-image/**`** (B-3/B-4/J-6: бамп пина CLI гоняет контракт конструкцией); infra-job (сборка образа без пуша) — `infra/**`. Required-совместимость: фильтрация внутри job-а (job стартует всегда, решает по diff). **Nightly/merge-queue — полный прогон без фильтров**; правило: новый верхнеуровневый каталог = правка фильтров тем же PR (F-5).
10. **Контрактные тесты (CC-5):** типы stream-json — в `core` (чистые serde), но `fake-executor` работает на **сырых JSONL-фикстурах** (литеральные строки, включая невалидные и «exit 0 без result») — общие типы разрешены только для сборки фикстур, кейсы порчи — строками: контракт не вырождается в roundtrip собственных структур (B-5).
11. **Гигиена репо и supply chain (CC-7):** `.gitignore` с `.env*` — в скелете; граница: в `.env` — только локальный dev-DSN, ничего из матрицы секретов ADR-0010 (C-2); `Cargo.lock` в git; версии точные, источник — `mise.toml`; **экшены GHA — по SHA** (CVE-2025-30066); `cargo deny check licenses` — отложено записью «до причины распространения» (C-5). TS-типы для `web/` — **только генерацией из Rust** (ts-rs/specta-класс) со сторожем по образцу `.sqlx`; ручное дублирование интерфейсов API — анти-паттерн (F-3); генератор — при открытии двери второго JS-пакета.

## 2. Почему

Раскладка — мейнстрим живых axum+React-проектов (Ryot, Komodo); шестёрка — верх research-консенсуса «5–7»; границы по каталогам работают на агентов-коммиттеров; mise — раннер без нового инструмента; каждый выбор внутри — по research с датами. Правки roast уточняют конструкцию CI/сборки/деплоя, не форму workspace: ни одна роль выбор A не оспорила.

## 3. Что отдаём

Церемония шести Cargo.toml (смягчена наследованием); static-serve без brotli и с bus factor ≈ 1 (запасной rust-embed, границы пересмотра в §4); chef инвалидирует recipe при правке любого Cargo.toml (редко); нарезка не бенчмаркалась — «профилировать `cargo build --timings` при жалобах»; корневой Cargo.toml — горячий файл (правило: зависимости добавляет владелец отдельным PR первым в очереди — H-4); кэш-бюджет GHA общий, деградация тихая (приоритизация кэшей — по первым признакам, H-6); интерим «SQL меняет владелец» — временное сужение автономии агентов до брокера GF-2; скелет — 15–25 ч честно (фазировка CC-8 ниже).

## 4. Границы пересмотра

Второй прод-сервис + холодная CI-пересборка дольше ~10 мин + второй разработчик → переоценка оркестратора сборки; жалобы на инкрементальную сборку → `--timings` и пересмотр нарезки (слияние дёшево в cargo; имена крейтов в инструкциях — из одного канонического файла, F-6); static-serve: 6–9 мес тишины при вышедшем мажоре axum → миграция на rust-embed не дожидаясь поломки (F-7); стабилизация выгрузки cache mounts в `type=gha` → пересмотр chef (F-8); второй JS-пакет → Bun workspaces + генератор TS-типов тем же PR; >2 классов ручных правок фильтров за квартал → генерация фильтров из структуры.

## 5. Операционные последствия

**Фазировка скелета (CC-8): три PR.** PR-1: workspace + шесть пустых крейтов + `mise.toml` (с пинами Rust/sqlx-cli) + CI (без docker-job) + `rust-toolchain`-пин + `.gitignore`/`.dockerignore` + runbook `prepare --check`. PR-2: dev-контур — vite-прокси на API, bacon, флаг `embed-static`. PR-3 (= GF-6): Dockerfile + chef + GHCR + деплой pull-ом. Bootstrap ворот — в два приёма (required checks появляются после первого прогона — ожидаемо, H-понимание). GF-5 стартует в PR-1 (первые крейты: `core`, `db` + миграции).

## 6. Критерий выполненности

ADR-0014 принят; скелет по фазировке §5 смержен через собственные ворота; `mise sqlx-prepare` и сторож `--check` работают; nightly-прогон без фильтров зелёный.
