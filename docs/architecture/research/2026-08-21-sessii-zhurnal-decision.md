# Decision summary: модель сессий и журнала (D-5)

- Дата: 2026-08-21 · Фаза: Decide (light) · Входы: discovery (Q1–Q3), design (A/B)
- Статус: **принято владельцем** («А», 2026-08-21). Roast на light не проводится; ревью реализации — `/architect:review` после GF-2.

## Выбранное

**A: вехи-указатели в сырьё** + общая часть design:

1. **Машина состояний сессии** — единое перечисление: `spawning` → `running` ⇄ `waiting_answer` (+ за флагом стопа-по-таймауту: `stopping` → `sleeping_cold`) → `completed` | `interrupted` | `failed`. Переводит только раннер; каждый переход — событие session_events; осиротевшие при старте бинаря → `interrupted` событием reconciliation.
2. **Родословная:** новая сессия ретрая/рестарта несёт `parent_session_id`; живая на задачу — одна (частичный UNIQUE ADR-0005); панель показывает цепочку.
3. **Вехи (Q2-б):** границы ходов (с `(raw_file, byte_from, byte_to)`), tool-вызовы (имя/длительность/статус, без аргументов), вопрос агента, interrupted, limit-белый-список, `raw_state`/ENOSPC. Доставка — только в `command_deliveries`.
4. **Drill-down (Q1):** «показать диалог» = API-срез raw-файла по смещениям вехи; читает раннер, права — RLS-контекст задачи; после janitor 30 дней — «сырьё истекло», остаются вехи и саммари. Live-хвоста в панель нет; «видимое = залогировано» — статусы и лента только из БД.
5. **Саммари (Q3-а):** исполнитель — при завершении и уходе в `waiting_answer`; умер без саммари → веха `summary_missing`, панель показывает предыдущее с пометкой.

## Почему

Единственный носитель клиентского текста (raw + то, что уже в БД по построению: команды — commands/ADR-0007, вопросы — session_events) — одна политика retention и «удалить с производными»; поза ADR-0005 «сырьё вне БД» не нарушается; глубина 30 дней — настройка janitor, не модель.

## Что отдаём

Диалог глубже 30 дней невосстановим (саммари и вехи остаются) — принято; битый/пропавший raw → срез недоступен, fallback — саммари; смещения пишутся writer-ом синхронно с вехой (обязательство GF-2).

## Операционные последствия

GF-2: writer вех со смещениями; endpoint среза сырья (авторизация по задаче); janitor уже есть (ADR-0005). GF-5: перечисление состояний сессии, `parent_session_id`, типы вех — v1-ядро; уточнения — forward-миграцией (право ADR-0005, раздел «Правила»).

## Границы пересмотра

Практика «нужен диалог старше 30 дней» → сперва retention janitor, при системности — пересмотр B; второй оператор с разными правами на сырьё → ревизия авторизации среза (D-7/D-16).
