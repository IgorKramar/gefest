# GF-6: Ф0 — инфраструктура периметра

- Статус: backlog (ADR-0010 принят)
- Фаза: Ф0 (параллельно GF-2)

Поднять периметр по ADR-0010: РФ-VM (рекомендация Timeweb Cloud, без публичного IPv4) + европейский VPS (exit node + Headscale 0.29.x + DERP); DERP-вторичка на РФ-VM; ACL с тегами и deny-by-default; устройства владельца (ноутбук + телефон) в tailnet; split-egress — только домены Anthropic через exit node; nftables «мост ↛ tailscale0»; SSH/консоль как аварийный путь; ключ pgcrypto файлом 0600 (+ офлайн-копия владельца); каналы алертов (Telegram-бот, ntfy, почта); стартовый пул scoped git-токенов (GitHub fine-grained + GitLab project tokens).

**Скоуп токенов для репозитория Гефеста (уточнено ревью PR-1, Review trail ADR-0010):** токен агента даёт пуш **в форк**, но не в `IgorKramar/gefest`. Причина: на `pull_request` GitHub исполняет workflow из головы PR вместе с его `permissions:`, поэтому PR из ветки основного репозитория может выдать себе права до чтения дифа человеком. PR из форка получает read-only токен и не видит секретов. Токен с правом создать ветку в основном репозитории обесценивает ограничение целиком.

Проверки готовности: с телефона через tailnet открывается owner-поверхность; из контейнера-исполнителя owner-порт недоступен (тест nftables/биндингов); `claude` из контейнера ходит в Anthropic через exit node; алерт-каналы доставляют «факт+ссылка»; restore-путь tailnet после падения EU VPS отрепетирован (снапшот+скрипт — совместно с GF-3).

Готово = все проверки зелёные + ходовые операции описаны в docs (enrolment passkey-устройства, пополнение пула, ротация ключа pgcrypto).
