- Фаза: Ф0.5 → Ф1 (первый Rust-код Гефеста)

## Сделано

**Скелет монорепы** ([план](../plans/2026-08-24-001-feat-skelet-monorepy-plan.md)): workspace (edition 2024, явный resolver 3) + шесть крейтов `hef-*` + `mise.toml` + пин тулчейна + CI из пяти job-ов + гигиена + runbook в `crates/db/README.md` + четыре сторожа с проверкой самих сторожей.

**Ворота на `main`** заведены и проверены отказом: ruleset `main protection`, пять required checks, запрет force-push и удаления, пустой bypass list (Review trail ADR-0012).

## Осталось

В `crates/core` + `crates/db`: bootstrap трёх ролей Postgres (пароли из env, не в миграциях) → миграции v1-ядра → прослойка доступа с CAS-retry.

Интерим ADR-0014: SQL-запросы меняет владелец, пока брокер ресурсов (GF-2) не выдаёт контейнеру задачи dev-БД.

## Состав первой волны (сужен 2026-08-24)

Разбор при входе в задачу; запись — Review trail ADR-0005. Конструкции ADR-0005 не пересматриваются, сужен только состав.

**11 таблиц + `audit_log`:** `actors`, `sessions`, `session_events`, `commands`, `command_deliveries`, `command_kinds`, `tasks`, `task_events`, `task_statuses`, `projects`, `project_counters`.

**Отложено в волну 2** (forward-миграциями): `consumer_offsets` — курсоры SSE нужны, когда есть панель; `journal` — приходит с ADR-0011 (чат и mailbox); `roles_profile` — до второго агента профиль живёт файлом в комплекте брокера.

**RLS — только на ядре доставки:** `sessions`, `session_events`, `commands`. Роли, `FORCE`, `audit_log` и отдельный шаг `hef migrate` остаются: их ретрофит означает смену владения объектами и пересмотр каждого запроса. Политики на `tasks`/`projects` при одном операторе не стерегут участника — агенты к БД не подключаются вовсе (граница ADR-0005: только через API/MCP), — и приходят со вторым оператором либо с открытием trust-двери D-16.

**Критерий среза** — первый сквозной сценарий: поставил задачу → агент работает → видны вехи → доставлено указание → получен ответ. Всё, что сценарий не задействует, ушло в волну 2.

## Проверки

Смоук-тесты (сценарий → признак провала):

1. **RLS-пул:** два запроса через один pooled-коннект от разных `actor_id` — второй видит чужие строки = провал.
2. **FTS:** `ts_debug('russian', …)` на корпусе из 20 реальных текстов — русские словоформы стеммятся, английские термины находятся.

Отрицательные тесты: UPDATE журнала — отказ; вторая живая команда старта — отказ; событие с прошлым `ts` не откатывает state; NULL-RLS-контекст — пусто; runtime-INSERT в lookup — отказ. Плюс CI-тест синхронизации Rust-enum ↔ lookup.

Тест на `PgListener` reconnect и gap-запись отложен вместе с `consumer_offsets`: он проверяет канал панели, которого в этой волне нет.

## Готово когда

Мерж + зелёный CI + миграции применяются на чистую БД + все проверки выше зелёные.

Оценка ADR-0005 на полные 14 таблиц была 30–40 ч. После сужения — меньше, но цифра не пересчитывалась: считать её точнее имеет смысл после первой миграции, когда появится фактический темп.
