- Статус: **в работе** — скелет PR-1 смержен 2026-08-24 ([PR #1](https://github.com/IgorKramar/gefest/pull/1), `4b9732e`); дальше миграции v1-ядра
- Фаза: Ф0.5 → Ф1 (первый Rust-код Гефеста)

**Скелет PR-1 сделан** ([план](../plans/2026-08-24-001-feat-skelet-monorepy-plan.md)): workspace (edition 2024, явный resolver 3) + шесть крейтов `hef-*` + `mise.toml` + пин тулчейна + CI из пяти job-ов + гигиена + runbook в `crates/db/README.md` + четыре сторожа с проверкой самих сторожей. Первый прогон на `main` зелёный.

**Осталось владельцу вне кода:** включить ruleset вторым приёмом — пять required status checks (`rust`, `front`, `migrations`, `contract`, `infra`); три правила (PR обязателен, запрет force-push, запрет удаления) заводятся независимо от прогонов. Подробности — Review trail ADR-0012. Затем в `crates/core`+`crates/db`: bootstrap трёх ролей Postgres (пароли из env, не в миграциях) + миграции v1-ядра (14 таблиц + audit_log, RLS-политики на ядро) + прослойка доступа с CAS-retry. Интерим ADR-0014: SQL-запросы меняет владелец (до брокера GF-2).

**Срез v1 сужен 2026-08-24** (Review trail ADR-0005). В первой волне — **11 таблиц + `audit_log`**: `actors`, `sessions`, `session_events`, `commands`, `command_deliveries`, `command_kinds`, `tasks`, `task_events`, `task_statuses`, `projects`, `project_counters`. Отложены в волну 2: `consumer_offsets` (нет панели), `journal` (приходит с ADR-0011), `roles_profile` (до второго агента — файл в комплекте брокера).

**RLS — только на ядре доставки**: `sessions`, `session_events`, `commands`. Роли, `FORCE`, `audit_log` и отдельный шаг `hef migrate` остаются — их ретрофит дороже. Политики на `tasks`/`projects` при одном операторе не защищают ни от чего и приходят со вторым оператором либо с D-16.

Критерий среза — первый сквозной сценарий: поставил задачу → агент работает → видны вехи → доставлено указание → получен ответ.

Смоук-тесты (сценарий → признак провала): (1) RLS-пул: два запроса через один pooled-коннект от разных actor_id — второй видит чужие строки = провал; (2) PgListener reconnect: kill соединения → события доезжают поллером, потеря без gap-записи = провал; (3) FTS: ts_debug('russian', корпус 20 реальных текстов) — русские словоформы стеммятся и английские термины находятся.

Отрицательные тесты: UPDATE журнала — отказ; вторая живая команда старта — отказ; событие с прошлым ts не откатывает state; NULL-RLS-контекст — пусто; runtime-INSERT в lookup — отказ. CI-тест синхронизации Rust-enum ↔ lookup.

Готово = мерж + зелёная проверка + миграции применяются на чистую БД + все тесты выше зелёные. Оценка: 30–40 ч (3–5 недель темпа).
